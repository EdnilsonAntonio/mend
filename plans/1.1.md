# Plan: 1.1 — Scaffold the app under test

## Goal

After this task the repository contains a minimal, dependency-free static web app in
`app-under-test/` that can be served on a fixed, known port (`3100`) with the single
command `npm run start:app`, plus the minimal root `package.json` needed to expose that
script. The page contains eight distinct interactive elements whose ids, classes, text,
and structure are the *stable baseline* that Task 1.2 will write assertions against and
Task 1.3 will deliberately drift. No framework, no build step, no npm dependencies, and
no application behaviour beyond the two DOM mutations tests need in order to make real
assertions.

## Files

- `package.json` — CREATE — root manifest, `private: true`, zero dependencies, exposes the
  single script `start:app`.
- `.gitignore` — CREATE — ignore `node_modules/` and `.DS_Store` so the first `npm install`
  (which will install nothing) cannot pollute the repo.
- `app-under-test/index.html` — CREATE — the entire app markup. This file is the selector
  contract for Tasks 1.2 and 1.3.
- `app-under-test/styles.css` — CREATE — presentation only. Exists so Task 2.1's DOM pruner
  has a real `<link>` to strip.
- `app-under-test/app.js` — CREATE — ~25 lines of vanilla browser JS providing exactly two
  behaviours (login status text, add-to-cart counter) so tests can assert on observable
  state rather than only clicking.
- `app-under-test/server.mjs` — CREATE — zero-dependency Node static file server bound to
  port 3100, serving only files inside `app-under-test/`.
- `app-under-test/README.md` — CREATE — the selector inventory table and the list of
  "reserved" hooks that Task 1.3 must not drift.

No other files. Do not create `agent/`, `runner/`, `dashboard/`, or `tests/`.

## Architectural decisions already made (do not revisit)

1. **Static server is hand-written with `node:http`, not the `serve` / `http-server`
   packages.** Rationale: the task says "no framework required" and this project's whole
   value proposition is auditability; a 60-line server keeps `npm install` at zero
   packages, keeps CI offline-capable, and removes a version-drift surface. The Builder
   must not add any dependency.
2. **Port is `3100`, hard-coded, no environment-variable override.** Rationale: the
   dashboard (Phase 6, Next.js) will want 3000; determinism matters more than flexibility
   here, and a silently-relocated app would produce confusing Playwright failures that
   look like selector drift. If the port is busy the server must fail loudly.
3. **No `data-*` attributes anywhere in the markup.** This app exists to be broken. A
   `data-testid` would give Task 1.2 a selector that never drifts, which would quietly
   invalidate Phase 1 through Phase 3. This is a hard rule, not a style preference.
4. **Behaviour code must not depend on any selector that Task 1.3 will drift.** `app.js`
   binds only to reserved hooks (see Implementation step 5). If renaming `#login-btn`
   broke the app's own JavaScript, the seeded breakage would stop being pure selector
   drift and would become an application failure — the exact category the system is
   required to *refuse* to heal.

## Implementation steps

1. **Create `package.json` at the repository root** with exactly this content:

   ```json
   {
     "name": "self-healing-e2e-tests",
     "version": "0.1.0",
     "private": true,
     "description": "Self-healing Playwright E2E tests: an agent that repairs selector drift and verifies every fix by re-execution.",
     "license": "UNLICENSED",
     "engines": {
       "node": ">=18.17.0"
     },
     "scripts": {
       "start:app": "node app-under-test/server.mjs"
     }
   }
   ```

   Do not add a `"type"` field, a `"main"` field, `dependencies`, or `devDependencies`.
   Do not run `npm install <anything>`.

2. **Create `.gitignore` at the repository root** with exactly these three lines:

   ```
   node_modules/
   .DS_Store
   ```

3. **Create `app-under-test/index.html`** with exactly the markup below. Ids, classes,
   element order, nesting, and visible text are all load-bearing — reproduce them
   verbatim. Do not add attributes, do not reorder, do not "improve" the copy.

   ```html
   <!DOCTYPE html>
   <html lang="en">
     <head>
       <meta charset="utf-8" />
       <meta name="viewport" content="width=device-width, initial-scale=1" />
       <title>Acme Store</title>
       <link rel="stylesheet" href="/styles.css" />
     </head>
     <body>
       <nav id="main-nav" class="main-nav">
         <span class="main-nav__brand">Acme Store</span>
         <ul class="main-nav__links">
           <li><a id="nav-home" class="nav-link" href="#home">Home</a></li>
           <li><a id="nav-products" class="nav-link" href="#products">Products</a></li>
           <li><a id="nav-cart" class="nav-link" href="#cart">Cart (<span id="cart-count">0</span>)</a></li>
         </ul>
       </nav>

       <main class="page">
         <section id="login-panel" class="panel">
           <h1 class="panel__title">Welcome back</h1>
           <form id="login-form" class="login-form" novalidate>
             <label class="field">
               <span class="field__label">Email</span>
               <input id="email" class="field__input" type="email" name="email" placeholder="you@example.com" />
             </label>
             <label class="field">
               <span class="field__label">Password</span>
               <input id="password" class="field__input" type="password" name="password" placeholder="Your password" />
             </label>
             <label class="field field--inline">
               <input id="remember-me" class="field__checkbox" type="checkbox" name="remember" />
               <span class="field__label">Remember me</span>
             </label>
             <button id="login-btn" class="btn btn--primary" type="submit">Sign In</button>
           </form>
           <p id="login-status" class="status" role="status"></p>
         </section>

         <section id="product-panel" class="panel">
           <h2 class="panel__title">Featured product</h2>
           <article id="product-card" class="product-card">
             <h3 class="product-card__title">Wireless Headphones</h3>
             <span class="product-card__price">$149.00</span>
             <p class="product-card__description">Over-ear, 30 hour battery life.</p>
             <button class="add-to-cart" type="button">Add to Cart</button>
           </article>
           <p id="cart-status" class="status" role="status"></p>
         </section>
       </main>

       <script src="/app.js" defer></script>
     </body>
   </html>
   ```

   Two properties of this markup are deliberate and must be preserved:
   - The Add-to-Cart button has **a class but no id** — this forces Task 1.2 to select it
     by class, which is what Task 1.3 scenario 2 (renamed class) needs.
   - `.product-card__price` is a **direct child** of `#product-card` — this is what makes
     Task 1.3 scenario 3 (element moved into a wrapper) able to break a child-combinator
     selector.
   - The substring "Sign In" (in any casing) appears exactly once in the rendered body
     text, on `#login-btn`. This is why the `<h1>` says "Welcome back" and not "Sign in to
     your account": Playwright's `getByText('Sign In')` is case-insensitive substring
     matching, and a second occurrence would produce a strict-mode violation in the
     *baseline* suite, which must be green.

4. **Create `app-under-test/styles.css`** with plain presentational rules only. Constraints
   the Builder must satisfy:
   - Target only the classes/ids present in step 3.
   - No rule may set `display: none`, `visibility: hidden`, `opacity: 0`, `pointer-events:
     none`, or a zero width/height on any element — Playwright actionability checks must
     never be blocked.
   - No `@keyframes`, no `transition`, no `animation` — animations cause flaky E2E timing.
   - No `@import`, no web fonts, no external URLs of any kind (the app must work offline).
   - Aim for roughly 40–70 lines: a system font stack on `body`, spacing on `.page`,
     `.panel`, `.field`, a horizontal `.main-nav__links` list, a visible `.btn--primary`,
     and a bordered `.product-card`.

5. **Create `app-under-test/app.js`** — a plain (non-module) browser script implementing
   exactly two behaviours and nothing else. It must reference *only* these reserved hooks:
   `#login-form`, `#login-status`, `#product-card`, `#cart-count`, `#cart-status`, plus
   `input[type="email"]` / `input[type="password"]` scoped inside the form.

   Behaviour A — login form submit:
   - Attach a `submit` listener to `#login-form`.
   - Call `event.preventDefault()` first.
   - Read `email` from `form.querySelector('input[type="email"]').value.trim()` and
     `password` from `form.querySelector('input[type="password"]').value`.
   - If either is the empty string, set `#login-status` `textContent` to exactly:
     `Please enter both email and password.`
   - Otherwise set `#login-status` `textContent` to exactly: `Signed in as ${email}`
     (e.g. `Signed in as user@example.com`).
   - Do not change any class, do not navigate, do not touch the checkbox.

   Behaviour B — add to cart:
   - Resolve the button with `document.querySelector('#product-card button')` (the card
     contains exactly one button; this deliberately avoids the `.add-to-cart` class, which
     Task 1.3 will rename).
   - On `click`: increment the integer in `#cart-count` `textContent` by 1 and write it
     back, then set `#cart-status` `textContent` to exactly:
     `Added Wireless Headphones to cart.` (the product name is hard-coded on purpose — do
     not read it from `.product-card__title`, which is a drift target).

   Prohibited in this file: `fetch`, `XMLHttpRequest`, `setTimeout`, `setInterval`,
   `localStorage`, `sessionStorage`, cookies, `history`/`location` changes, any
   credential checking, any routing, any state object. If `document.querySelector` returns
   `null` for a hook, the script may simply return early — no error handling framework.

6. **Create `app-under-test/server.mjs`** — a zero-dependency ESM script. Required
   behaviour, exactly:
   - `const PORT = 3100;` as a top-level named constant. No `process.env` fallback.
   - `ROOT` = the directory containing `server.mjs`, derived via
     `path.dirname(fileURLToPath(import.meta.url))`. Files outside `ROOT` are never served.
   - Uses only `node:http`, `node:fs` (or `node:fs/promises`), `node:path`, `node:url`.
   - Request handling:
     | Condition | Response |
     | --- | --- |
     | method not `GET` and not `HEAD` | `405`, `text/plain; charset=utf-8`, body `Method Not Allowed` |
     | pathname `/` | serve `index.html` |
     | resolved path escapes `ROOT` (e.g. `..`, encoded traversal) | `403`, `text/plain; charset=utf-8`, body `Forbidden` |
     | resolved path is missing or is a directory | `404`, `text/plain; charset=utf-8`, body `Not Found` |
     | otherwise | `200` with the file bytes |
   - Pathname must be taken from `new URL(req.url, 'http://localhost')`.`pathname` and
     passed through `decodeURIComponent` **before** the traversal check, so that
     `%2e%2e%2f` cannot bypass it.
   - Content type from this exact map, defaulting to `application/octet-stream`:
     `.html` → `text/html; charset=utf-8`, `.css` → `text/css; charset=utf-8`,
     `.js` → `text/javascript; charset=utf-8`, `.json` → `application/json; charset=utf-8`,
     `.svg` → `image/svg+xml`, `.ico` → `image/x-icon`.
   - Every response (including errors) must set `Cache-Control: no-store`. This is
     required: Task 1.3 toggles breakage by editing `index.html` on disk, and a cached
     response would make the app look un-broken.
   - Every `200`/error response sets `Content-Length`. For `HEAD`, send headers and end
     with no body.
   - On successful `listen`, print exactly:
     `app-under-test listening on http://localhost:3100`
     (This line is the readiness signal a later Playwright `webServer` config can wait on.)
   - On a server `error` event with `code === 'EADDRINUSE'`, print to `stderr`
     `Port 3100 is already in use. Stop the other process and retry.` and call
     `process.exit(1)`. Any other server error: print the error and `process.exit(1)`.
   - No auto-port-selection, no directory listing, no gzip, no watch/reload.

7. **Create `app-under-test/README.md`** containing:
   - A one-line statement that this app is test scaffolding, not a product, and that it
     exists to be broken.
   - How to run it: `npm run start:app` → http://localhost:3100.
   - A **Selector inventory** table with the columns `Element | Selector | Purpose` listing
     all eight interactive elements plus `#cart-count`, `#login-status`, `#cart-status`,
     `.product-card__price`, `.product-card__title`.
   - A **Reserved hooks** section stating that `#login-form`, `#login-status`,
     `#product-card`, `#cart-count`, and `#cart-status` are wired to `app.js` and must not
     be renamed or restructured by the Task 1.3 breakage script.
   - A **No `data-*` attributes** rule with the one-sentence rationale from decision 3.

8. **Verify locally** (Builder must actually run these, from the repo root):
   ```sh
   npm run start:app &   # then, after ~1s:
   curl -s -o /dev/null -w '%{http_code}\n' http://localhost:3100/            # 200
   curl -s -o /dev/null -w '%{http_code}\n' http://localhost:3100/styles.css  # 200
   curl -s -o /dev/null -w '%{http_code}\n' http://localhost:3100/app.js      # 200
   curl -s -o /dev/null -w '%{http_code}\n' http://localhost:3100/nope.html   # 404
   curl -s -o /dev/null -w '%{http_code}\n' 'http://localhost:3100/%2e%2e%2fpackage.json'  # 403 (or 404)
   curl -s http://localhost:3100/ | diff - app-under-test/index.html          # no diff
   ```
   Then kill the background process. Report the observed status codes in the Verification
   section of the build report.

## Risks

- **Builder reaches for a dependency.** The most likely deviation is `npx serve` or adding
  `http-server`. If the hand-written server feels like too much, that is not grounds to
  add a package — report "Blocked / unclear" instead. Zero dependencies is an acceptance
  criterion.
- **Port 3100 already in use on the dev machine.** The server must fail loudly (criterion
  above) rather than pick another port. If 3100 is genuinely occupied by something the
  developer needs, that is an escalation to the human, not a silent port change — the
  number is duplicated into Task 1.2's Playwright `baseURL`, so changing it here without
  telling anyone breaks the next task.
- **Accidental text duplication creating strict-mode ambiguity.** Adding any copy
  containing "sign in", "log in", "add to cart", or "wireless headphones" outside the
  specified elements will make Task 1.2's baseline suite fail with a strict-mode violation
  that looks like a bug in the healing system. Keep the copy exactly as written.
- **Coupling `app.js` to a drift target.** If behaviour breaks when Task 1.3 renames
  `#login-btn` or `.add-to-cart`, the seeded failures stop being pure selector drift and
  the failure classifier in Task 3.1 will (correctly) refuse to heal them, silently
  invalidating Phase 3. This is why step 5 restricts `app.js` to reserved hooks.
- **Traversal check ordering.** Decoding the URL *after* the containment check is a real
  bypass. Decode first, resolve second, compare against `ROOT` third.
- **Trailing-newline mismatch in the byte-identical body check.** Serve the file bytes
  verbatim (`fs.readFile`, no string post-processing) so `curl | diff` is clean.
