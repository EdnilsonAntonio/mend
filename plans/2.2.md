# Plan: 2.2 — `query_selector`

## Goal

After this task the repository can answer, deterministically and with no OpenAI dependency,
the question **"if I use this selector, what would I actually hit?"** — returning an exact
match count plus a bounded, structured preview of each matched element (tag, id, classes,
`role`, normalized text, visibility). Zero, one, and many matches are all ordinary
successful results. A syntactically invalid selector is also an ordinary result: the call
resolves with `error: { kind: 'invalid-selector', message }` and never rejects. The tool
reads the page and never mutates it, never clicks, never waits, and never retries. It is
the second of the three agent tools and, like `get_dom_snapshot`, it is built and tested
standalone before any model is involved.

---

## Open questions — answer these at the approval gate

The plan below is written assuming the **recommended** option in each case. If the human
accepts the recommendations, they become binding and the Builder makes no decision here. If
the human picks otherwise, this plan must be revised before the Builder is invoked.

### Q1 — What is a "preview"? → **Recommend B**

TASKS.md says "a short text preview of each"; DESIGN.md says `previews[]` without saying
what an element of that array is.

* **A.** `previews: string[]` — just the truncated text of each match.
* **B (recommended).** `previews: SelectorMatchPreview[]` — a small fixed record:
  `{ index, tagName, id, classList, role, text, visible }`.

Rationale for B: with A the agent cannot tell `<button id="signin-button">Sign In</button>`
from `<span class="field__label">Sign In</span>`, which is exactly the discrimination
scenario 4 requires and exactly the "wrong element matched" failure mode
REQUIREMENTS.md names. `text` is still present, so B is a superset of A. The record is
fixed-width and capped, so the token cost stays bounded.

### Q2 — Does `matchCount` count hidden elements? → **Recommend A**

* **A (recommended).** `matchCount` is the raw number of elements the selector resolves to,
  hidden or not. Visibility is reported per preview via `visible`.
* **B.** `matchCount` counts only visible elements.

Rationale for A: the confidence gate in DESIGN.md grants `high` on "exactly 1 DOM match".
Filtering hidden elements out of the count would let a selector that genuinely matches two
elements be reported as unique, which manufactures confidence the DOM does not support.
Raw count is the honest signal; `visible` carries the extra nuance without hiding anything.

### Q3 — What does the CLI exit with when the selector is invalid? → **Recommend A**

* **A (recommended).** Exit `0`. An invalid selector is a *successful tool call that
  returned a structured error* — which is literally the third acceptance criterion in
  TASKS.md. Non-zero exits are reserved for CLI usage errors (`2`) and infrastructure
  failure such as browser launch or navigation (`1`).
* **B.** Exit `1` on any `error !== null`.

Rationale for A: it keeps "never throws on invalid selector syntax" objectively testable at
the process level, and it matches how the Phase 3 agent will consume the tool — an invalid
selector is feedback to the model, not a crash.

---

## Reconciliation note: this result shape is a superset of DESIGN.md's

DESIGN.md's tool-contract table says `query_selector` returns `{ matchCount, previews[] }`.
TASKS.md additionally requires that an invalid selector "returns a structured error
instead". Those two cannot both be satisfied by a two-field object. This plan therefore
returns `{ selector, matchCount, previews, previewsTruncated, error }` — DESIGN.md's two
fields verbatim, plus the three fields TASKS.md's third acceptance criterion forces. This is
an addition, not a contradiction, and it is recorded here so the Reviewer does not read it
as spec drift. `spec/DESIGN.md` is **not** edited by this task.

## Architectural decisions already made (do not revisit)

1. **The selector dialect is Playwright's, not raw CSS.** All matching goes through
   `page.locator(selector)`. It is not optional: the baseline suite's scenario-4 target is
   `button:has-text("Sign In")`, a Playwright engine pseudo-class that
   `document.querySelectorAll` rejects with a `SyntaxError`. The agent receives the failing
   selector verbatim from a spec file, so `query_selector` must accept exactly the dialect
   the spec files are written in. Do **not** add a CSS-only fallback path.

2. **The tool takes a live Playwright `Page` the caller has already navigated**, with a
   `querySelectorFromUrl` convenience wrapper that launches and closes its own browser for
   standalone/CLI use. This is the same shape as Task 2.1 (`getDomSnapshot` /
   `captureDomSnapshotFromUrl`) and the same answer to "at failure point" that 2.1's Q1
   settled. No new fixture, reporter, or frozen-artifact mechanism.

3. **Preview extraction happens in the browser, in one `locator.evaluateAll` call.** One
   round trip, one atomic view of the DOM, and `matchCount` and `previews` cannot disagree
   with each other. The alternative — N × 6 Node-side `nth(i).getAttribute(...)` calls —
   is more round trips and introduces auto-waiting APIs this tool must not use.

4. **The browser-context function is a plain ESM JavaScript file with a hand-written
   `.d.ts`, exactly as `dom-prune.js` is.** `locator.evaluateAll(fn, arg)` ships
   `fn.toString()` into an isolated browser context, so the same constraint and the same
   `tsx` / esbuild `keepNames` / `__name` hazard documented in `plans/2.1.md` decision 9
   applies verbatim. Files: `agent/tools/selector-preview.js` +
   `agent/tools/selector-preview.d.ts`. Do not author this as `.ts`. Do not define
   `globalThis.__name`. Do not inline the function as a template string.

5. **The tool is read-only and non-waiting.** Permitted Playwright surface:
   `page.locator()`, `locator.count()`, `locator.evaluateAll()`, and (in the URL wrapper
   only) `chromium.launch`, `browser.newContext`, `context.newPage`, `page.goto`,
   `browser.close`. Forbidden anywhere in `query-selector.ts`: `click`, `hover`, `fill`,
   `check`, `press`, `scrollIntoViewIfNeeded`, `waitFor`, `waitForSelector`,
   `waitForTimeout`, `textContent()`, `innerText()`, `isVisible()`, `getAttribute()`,
   `screenshot`, `addInitScript`, `addScriptTag`.

6. **Preview output is bounded by two named constants**, never by an unbounded loop:
   `QUERY_SELECTOR_MAX_PREVIEWS = 10` and `QUERY_SELECTOR_MAX_PREVIEW_TEXT_LENGTH = 80`.
   `matchCount` is always the true count even when previews are capped;
   `previewsTruncated` reports the difference.

7. **No OpenAI tool-schema wrapper in this task.** The JSON tool definition the model sees
   is Phase 3's job. Same as 2.1 decision 7.

8. **Tool tests go in the existing `agent/tools/__tests__/` directory under the existing
   `playwright.tools.config.ts`.** No new Playwright config. `tests/` stays frozen at 5
   specs and `npm run test:e2e` must still report exactly 5 passed.

9. **The CLI contract form is direct `npx tsx` invocation**; `npm run --silent
   tool:query-selector` is the documented convenience wrapper. Identical to 2.1
   decision 10. No `.npmrc`, no `loglevel`, no `--silent` baked into the script value, no
   banner-stripping code.

10. **Breakage-on behaviour is verified by the Builder's shell commands, not by a Playwright
    test.** A test that shells out to `npm run break:on` would leave the repository broken
    if it crashed mid-test. 2.1 set this precedent; follow it.

### 2. `agent/tools/selector-preview.js`

**Plain JavaScript. ESM. No TypeScript syntax** — no type annotations, no `interface`, no
`as`, no `satisfies`, no generics. JSDoc comments only.

**Hard constraint (self-containment):** `describeElements` is serialized by
`Function.prototype.toString()` and re-evaluated inside the browser. It must reference
**nothing** outside its own body: no imports, no module-scope constants, no other
module-scope functions, and no globals other than `window` and `Math`. Every helper and
every constant lives inside the function body. Every tunable arrives through `req`.

The file's entire module scope is: a JSDoc block, `function describeElements(elements, req)
{ ... }`, and `export { describeElements };`. Nothing else.

Behaviour, exactly:

```
function describeElements(elements, req) {
  const matchCount = elements.length;
  const limit = Math.min(matchCount, req.maxPreviews);
  const previews = [];

  for (let i = 0; i < limit; i++) {
    const el = elements[i];

    const rawText = (el.textContent === null ? '' : el.textContent)
      .replace(/\s+/g, ' ')
      .trim();
    const text = rawText.length > req.maxPreviewTextLength
      ? rawText.slice(0, req.maxPreviewTextLength) + '…'
      : rawText;

    const idAttr = el.getAttribute('id');
    const roleAttr = el.getAttribute('role');
    const classAttr = el.getAttribute('class');

    previews.push({
      index: i,
      tagName: el.tagName.toLowerCase(),
      id: idAttr === null || idAttr === '' ? null : idAttr,
      classList: classAttr === null
        ? []
        : classAttr.split(/\s+/).filter((c) => c.length > 0),
      role: roleAttr === null || roleAttr === '' ? null : roleAttr,
      text: text,
      visible: el.getClientRects().length > 0
        && window.getComputedStyle(el).visibility !== 'hidden',
    });
  }

  return { matchCount: matchCount, previews: previews };
}

export { describeElements };
```

Notes the Builder must honour:
- `visible` uses exactly that formula. It is Playwright's documented definition of
  visibility (non-empty bounding box and `visibility !== 'hidden'`). Do not substitute
  `offsetParent`, `display`, or `IntersectionObserver`.
- Empty text yields `''`, never `null`.
- The `.filter((c) => c.length > 0)` callback is an anonymous inline arrow on purpose. Do
  **not** hoist it into a named helper — a named nested function is what triggers the
  `__name` hazard.
- `classList` is deliberately uncapped; the app under test has at most two classes per
  element. This is recorded as a v1 limitation in the README, not fixed here.
- Nothing in this function writes to the DOM.

### 3. `agent/tools/query-selector.ts`

TypeScript, strict. Imports:

```ts
import type { Page } from '@playwright/test';
import { chromium } from '@playwright/test';
import {
  describeElements,
  type SelectorPreviewRequest,
  type SelectorMatchPreview,
} from './selector-preview.js';

export type { SelectorMatchPreview };
```

`SelectorMatchPreview` is defined once, in `selector-preview.d.ts`, and re-exported here so
consumers import it from `query-selector.js`. Do not redeclare it.

Exported constants:

```ts
export const QUERY_SELECTOR_MAX_PREVIEWS = 10;
export const QUERY_SELECTOR_MAX_PREVIEW_TEXT_LENGTH = 80;

export const DEFAULT_QUERY_SELECTOR_OPTIONS: QuerySelectorOptions = {
  maxPreviews: QUERY_SELECTOR_MAX_PREVIEWS,
  maxPreviewTextLength: QUERY_SELECTOR_MAX_PREVIEW_TEXT_LENGTH,
};

export const EMPTY_SELECTOR_MESSAGE = 'selector must be a non-empty string';
```

`EMPTY_SELECTOR_MESSAGE` is exported so the test can assert the exact string without
duplicating a literal.

```ts
export async function querySelector(
  page: Page,
  selector: string,
  overrides?: Partial<QuerySelectorOptions>,
): Promise<QuerySelectorResult>
```

Behaviour, in this exact order. There is **no** loop, **no** retry, and **no** `await` on
anything that auto-waits.

1. `const options = { ...DEFAULT_QUERY_SELECTOR_OPTIONS, ...overrides };`
2. **Empty guard.** If `selector.trim().length === 0`, return immediately:
   ```ts
   { selector, matchCount: 0, previews: [], previewsTruncated: false,
     error: { kind: 'invalid-selector', message: EMPTY_SELECTOR_MESSAGE } }
   ```
   Do not call Playwright at all in this branch.
3. **Phase 1 — validate and count.** Inside a single `try`:
   ```ts
   const locator = page.locator(selector);
   const phase1Count = await locator.count();
   ```
   Both statements are inside the `try`, because Playwright may reject the selector either
   at construction or at first use. On any throw, return:
   ```ts
   { selector, matchCount: 0, previews: [], previewsTruncated: false,
     error: { kind: 'invalid-selector', message: <the caught error's message> } }
   ```
   Extract the message with `error instanceof Error ? error.message : String(error)` — the
   same idiom already used in `get-dom-snapshot.cli.ts`.
4. **Phase 2 — describe.** Inside a second `try`:
   ```ts
   const req: SelectorPreviewRequest = {
     maxPreviews: options.maxPreviews,
     maxPreviewTextLength: options.maxPreviewTextLength,
   };
   const raw = await locator.evaluateAll(describeElements, req);
   ```
   This is the **only** `evaluateAll` / `evaluate` call in the file. On success return:
   ```ts
   { selector, matchCount: raw.matchCount, previews: raw.previews,
     previewsTruncated: raw.matchCount > raw.previews.length, error: null }
   ```
   On any throw return:
   ```ts
   { selector, matchCount: phase1Count, previews: [], previewsTruncated: phase1Count > 0,
     error: { kind: 'evaluation-failed', message: <the caught error's message> } }
   ```
5. `selector` in the result is always the caller's input string **verbatim** — never
   trimmed, normalized, or rewritten.

`evaluation-failed` is defensive: it is not reachable against a static page and has no
dedicated test. It exists so the error type is honest and so Phase 3 can distinguish "your
selector is bogus" from "the browser died".

```ts
export async function querySelectorFromUrl(
  selector: string,
  url: string,
  overrides?: Partial<QuerySelectorOptions>,
): Promise<QuerySelectorResult>
```

Launches `chromium.launch({ headless: true })`, creates a context and page,
`await page.goto(url, { waitUntil: 'load' })`, calls `querySelector(page, selector,
overrides)`, and closes the browser in a `finally` block so it closes even on failure.
Returns the result. No retries, no default URL — the caller supplies it. Argument order is
`(selector, url, overrides)`, mirroring `querySelector(page, selector, overrides)`.

### 4. `agent/tools/cli/query-selector.cli.ts`

Zero interactivity, no argument-parsing library. Modelled on
`agent/tools/cli/get-dom-snapshot.cli.ts`.

```
Usage: npx tsx agent/tools/cli/query-selector.cli.ts <selector> [--url=<url>] [--json]
   or: npm run --silent tool:query-selector -- <selector> [--url=<url>] [--json]
```

Argument parsing, exactly:
- `const args = process.argv.slice(2);`
- `const json = args.includes('--json');`
- `const urlArg = args.find((a) => a.startsWith('--url='));`
- `const url = urlArg === undefined ? 'http://localhost:3100/' : urlArg.slice('--url='.length);`
- `const positionals = args.filter((a) => !a.startsWith('--'));`
- If `positionals.length !== 1`: print to stderr the two usage lines above, then
  `process.exit(2)`. Nothing on stdout.
- `const selector = positionals[0];` — guard the `noUncheckedIndexedAccess`
  `string | undefined` by checking `positionals.length !== 1` first and then narrowing with
  an explicit `if (selector === undefined) { ...exit(2) }`, not with `!`.

Then `const result = await querySelectorFromUrl(selector, url);` and:

- With `--json`: `console.log(JSON.stringify(result, null, 2));` and nothing else on stdout
  or stderr.
- Without `--json`, stdout gets a header line followed by one line per preview:
  ```
  selector=<selector> matches=<matchCount> shown=<previews.length> truncated=<previewsTruncated> error=<none|invalid-selector|evaluation-failed>
  [<index>] <tagName> id=<id ?? '-'> class=<classList.join(' ') || '-'> role=<role ?? '-'> visible=<visible> text=<JSON.stringify(text)>
  ```
  and, when `result.error !== null`, exactly one additional line on **stderr**:
  ```
  query_selector error: <error.message>
  ```
- Exit `0` after printing a result, **including when `result.error !== null`** (Q3).
- On a thrown error from `querySelectorFromUrl` (browser launch or navigation failure):
  print `query_selector failed: <message>` to stderr and `process.exit(1)`.

The CLI must contain no logic that inspects, filters, or strips its own output stream.

### 5. `agent/tools/__tests__/query-selector.spec.ts`

Twelve tests using `@playwright/test`, wrapped in `test.describe('query_selector', ...)`.
Tests 9 and 10 build their own DOM with `page.setContent(...)`; the rest hit the live app
at `/`. Test 11 launches its own browser.

1. **`reports exactly one match for a unique id selector`** — `goto('/')`;
   `querySelector(page, '#login-btn')`. Assert `matchCount === 1`, `previews.length === 1`,
   `previewsTruncated === false`, `error === null`, `previews[0].tagName === 'button'`,
   `previews[0].id === 'login-btn'`, `previews[0].text === 'Sign In'`,
   `previews[0].visible === true`.
2. **`reports zero matches without treating it as an error`** — `goto('/')`;
   `querySelector(page, '#does-not-exist')`. Assert `matchCount === 0`,
   `previews` is `[]`, `previewsTruncated === false`, and **`error === null`**.
3. **`reports more than one match for an ambiguous selector`** — `goto('/')`;
   `querySelector(page, '.nav-link')`. Assert `matchCount === 3`, `previews.length === 3`,
   `error === null`, and the three `previews[i].id` values are `nav-home`, `nav-products`,
   `nav-cart` in that order.
4. **`returns a structured error for invalid selector syntax instead of throwing`** —
   `goto('/')`; for each of `'div[unclosed'` and `'button:has-text('`, await
   `querySelector(page, s)` and assert the promise **resolves** (do not wrap in
   `expect(...).rejects`), `error !== null`, `error.kind === 'invalid-selector'`,
   `error.message.length > 0`, `matchCount === 0`, `previews` is `[]`.
5. **`returns a structured error for an empty selector`** — `goto('/')`;
   `querySelector(page, '   ')`. Assert `error?.kind === 'invalid-selector'` and
   `error?.message === EMPTY_SELECTOR_MESSAGE` (imported, not a duplicated literal).
6. **`supports Playwright text pseudo-classes`** — `goto('/')`;
   `querySelector(page, 'button:has-text("Sign In")')`. Assert `error === null`,
   `matchCount === 1`, `previews[0].id === 'login-btn'`. This is the scenario-4 selector and
   the proof of decision 1.
7. **`does not mutate the live page`** — `goto('/')`; record
   `await page.evaluate(() => document.documentElement.outerHTML)`; run
   `querySelector(page, '*')`; record it again; assert the two strings are strictly equal.
8. **`caps previews but still reports the true match count`** — `goto('/')`;
   `querySelector(page, '*')`. Assert `matchCount > QUERY_SELECTOR_MAX_PREVIEWS`,
   `previews.length === QUERY_SELECTOR_MAX_PREVIEWS`, `previewsTruncated === true`,
   `error === null`.
9. **`truncates long preview text`** — `page.setContent` with
   `<p id="long">${'y'.repeat(500)}</p>` inside a minimal document;
   `querySelector(page, '#long')`. Assert `previews[0].text.endsWith('…')` and
   `previews[0].text.length === QUERY_SELECTOR_MAX_PREVIEW_TEXT_LENGTH + 1`.
10. **`reports visibility per match`** — `page.setContent` with
    `<p id="shown">x</p><p id="gone" style="display:none">y</p>`;
    `querySelector(page, 'p')`. Assert `matchCount === 2`,
    `previews[0].visible === true`, `previews[1].visible === false`.
11. **`querySelectorFromUrl works without a test fixture page`** — call
    `querySelectorFromUrl('#login-btn', 'http://localhost:3100/')` directly (it launches and
    closes its own browser). Assert `matchCount === 1` and `previews[0].id === 'login-btn'`.
12. **`populates every preview field`** — `goto('/')`; two calls:
    - `querySelector(page, '#product-card > .product-card__price')` → `matchCount === 1`,
      `previews[0].tagName === 'span'`, `previews[0].id === null`,
      `previews[0].classList` deep-equals `['product-card__price']`,
      `previews[0].role === null`, `previews[0].text === '$149.00'`,
      `previews[0].index === 0`.
    - `querySelector(page, '#login-status')` → `previews[0].role === 'status'` and
      `previews[0].text === ''` (empty string, not `null`).

Exactly twelve tests. Do not add a thirteenth, and in particular do not add a test that
shells out to `npm run break:on` — see decision 10.

**Append only.** Every existing line stays byte-identical; the new content goes after the
current last line. Add a top-level `## query_selector` section with these subsections, in
this order:

1. **Intro** — the second of three tools; reports how many elements a candidate selector
   resolves to and what they are, without committing to anything.
2. **Public API** — the exact signatures of `querySelector` and `querySelectorFromUrl` and
   the `QuerySelectorResult`, `SelectorMatchPreview`, `SelectorError`, and
   `QuerySelectorOptions` shapes, copied from the Interfaces section below.
3. **Selector dialect** — state that selectors go through `page.locator()`, so Playwright
   engine syntax (`:has-text()`, `text=`, `>>`) is supported in addition to CSS, and state
   why: the baseline suite's scenario-4 target is `button:has-text("Sign In")` and the agent
   receives selectors verbatim from spec files.
4. **Bounds** — `QUERY_SELECTOR_MAX_PREVIEWS = 10`,
   `QUERY_SELECTOR_MAX_PREVIEW_TEXT_LENGTH = 80`; state that `matchCount` is always the true
   count even when previews are capped, and that `previewsTruncated` reports the difference.
5. **Errors** — the table below, verbatim in substance:

   | Situation | `matchCount` | `previews` | `error` | Call rejects? |
   | --- | --- | --- | --- | --- |
   | 0 matches | `0` | `[]` | `null` | no |
   | 1+ matches | true count | up to 10 | `null` | no |
   | empty / whitespace selector | `0` | `[]` | `invalid-selector` | no |
   | unparseable selector | `0` | `[]` | `invalid-selector` | no |
   | browser evaluation failed | phase-1 count | `[]` | `evaluation-failed` | no |

   State explicitly: **`querySelector` never rejects for a bad selector.** Zero matches is
   not an error.
6. **Read-only guarantee** — the tool only counts and reads; it never clicks, hovers,
   scrolls, fills, waits, or retries, and a test asserts `document.documentElement.outerHTML`
   is unchanged across a call.
7. **Why `selector-preview.js` is JavaScript, not TypeScript** — one paragraph, same reason
   as `dom-prune.js`: the function is shipped to the browser by `locator.evaluateAll` via
   `Function.prototype.toString()`, so it must be self-contained; `tsx` runs esbuild with
   `keepNames: true` and injects `__name(f, "f")` into named nested functions when
   transpiling `.ts`, which throws `ReferenceError` in the browser. End with the warning:
   **do not rename this file to `.ts`, and do not "fix" a `__name` error by defining
   `globalThis.__name`.** Cross-reference the existing `dom-prune.js` section.
8. **Running standalone** — both forms, exactly:
   ```sh
   npm run start:app                                            # in another shell

   # contract form — stdout is exactly the tool's output
   npx tsx agent/tools/cli/query-selector.cli.ts '#login-btn'
   npx tsx agent/tools/cli/query-selector.cli.ts '.nav-link' --json
   npx tsx agent/tools/cli/query-selector.cli.ts 'button:has-text("Sign In")' --url=http://localhost:3100/

   # convenience form — note --silent, which suppresses npm's script banner
   npm run --silent tool:query-selector -- '#login-btn'
   npm run --silent tool:query-selector -- '#login-btn' --json
   ```
   Immediately below, state the exit codes: `0` = a result was produced (including a
   structured `error`), `2` = CLI usage error, `1` = browser launch or navigation failure.
   Also repeat that plain `npm run` without `--silent` prepends a banner to stdout and that
   `.npmrc` is not the fix.
9. **Known limitations (v1)** — each stated plainly:
   - `role` is the literal `role` attribute only; implicit ARIA roles are not computed, so
     `<button>` reports `role: null`.
   - `classList` is not capped; an element with a very large class list produces a large
     preview. Not a problem for the app under test.
   - Only the main frame is queried. Shadow DOM piercing is whatever `page.locator()` does
     by default; no extra traversal is implemented.
   - `visible` is a point-in-time read; the tool does not wait for anything to appear.

/**
 * Request parameters for describeElements.
 * The implementation is in selector-preview.js — plain JavaScript on purpose. See
 * agent/tools/README.md, "Why selector-preview.js is JavaScript, not TypeScript".
 */
export interface SelectorPreviewRequest {
  /** Maximum number of matched elements to describe. */
  readonly maxPreviews: number;
  /** Preview text longer than this is truncated and suffixed with U+2026. */
  readonly maxPreviewTextLength: number;
}

/** One matched element, described. */
export interface SelectorMatchPreview {
  /** Zero-based position of this element among the matches. */
  readonly index: number;
  /** Lowercase tag name. */
  readonly tagName: string;
  /** The `id` attribute, or null when absent or empty. */
  readonly id: string | null;
  /** The `class` attribute split on whitespace. Empty array when absent. */
  readonly classList: readonly string[];
  /** The literal `role` attribute, or null. Implicit ARIA roles are not computed. */
  readonly role: string | null;
  /** Whitespace-collapsed, trimmed, truncated text content. Empty string, never null. */
  readonly text: string;
  /** getClientRects().length > 0 && computed visibility !== 'hidden'. */
  readonly visible: boolean;
}

/** Result returned by describeElements. */
export interface SelectorPreviewResult {
  /** Total number of matched elements, regardless of how many were described. */
  readonly matchCount: number;
  /** At most `req.maxPreviews` entries. */
  readonly previews: readonly SelectorMatchPreview[];
}

/**
 * Runs inside the browser via locator.evaluateAll. Must reference nothing outside its own
 * body except the globals `window` and `Math`.
 */
export declare function describeElements(
  elements: Element[],
  req: SelectorPreviewRequest,
): SelectorPreviewResult;

  /** Maximum number of matched elements described in `previews`. */
  readonly maxPreviews: number;

}

  /** The caller's selector, verbatim and untrimmed. */
  readonly selector: string;

## Risks

- **`describeElements` closes over something and dies inside the browser.** Same failure
  mode as `dom-prune.js`, and `npm run typecheck` will not catch it. A module-scope constant
  becomes `ReferenceError: X is not defined` at runtime. Every constant and helper must be
  declared inside the function body. All twelve tests exercise the real `evaluateAll` path,
  so `npm run test:tools` catches it immediately. If a `ReferenceError` appears, move the
  identifier inside the function. Do **not** inline the function as a template string and do
  **not** define the missing identifier as a global.

- **Someone renames `selector-preview.js` to `.ts`.** It will typecheck and it will pass
  `npm run test:tools` (Playwright's Babel transform is clean), then the CLI will fail with
  `ReferenceError: __name is not defined`. If the Builder believes `.ts` should work, it must
  report **Blocked / unclear** rather than change the extension.

- **`page.locator()` does not throw where the plan assumes it does.** Playwright may defer
  selector parsing from construction to first use, or vice versa, across versions. The plan
  puts *both* `page.locator(selector)` and `await locator.count()` inside the same `try`
  precisely so it does not matter which one throws. If neither throws for
  `'div[unclosed'` — i.e. Playwright silently returns 0 matches for a malformed selector —
  report **Blocked / unclear** with the observed behaviour. Do **not** add a hand-rolled
  selector validator or a `document.querySelectorAll` pre-check to force an error; that
  would break the `:has-text()` dialect requirement.

- **`locator.count()` on `'*'` is large or slow.** ~40 elements on this page. If it is
  materially slow, that is a signal something is auto-waiting; check that no forbidden API
  crept in. Do not add a timeout or a cap to `count()`.

- **Test 8's `'*'` selector matches fewer than 11 elements.** The pristine page has roughly
  40 elements (`html`, `head`, `title`, `body`, `nav`, `ul`, 3×`li`, 3×`a`, `main`,
  2×`section`, `form`, 3×`label`, 3×`input`, `button`, `article`, and more), so this is safe.
  If the assertion fails, investigate whether `matchCount` is being sourced from
  `previews.length` instead of `elements.length` — that is the likely bug. Do not weaken the
  assertion.

- **Test 9's exact length assertion (`=== 81`).** This asserts 80 characters plus the
  one-code-unit U+2026. It is exact on purpose so that an off-by-one in the truncation is
  caught. `'y'.repeat(500)` has no whitespace, so collapsing and trimming are no-ops. If it
  fails at 80 or 82, fix the slice, do not relax the assertion to `<=`.

- **`visible` disagrees with Playwright's `isVisible()`.** The formula in step 2 is
  Playwright's documented definition, but it is a reimplementation. If a future case
  disagrees, that is a documented v1 approximation — do **not** "fix" it by calling
  `locator.nth(i).isVisible()`, which is a forbidden auto-waiting API and N extra round
  trips.

- **`noUncheckedIndexedAccess` friction.** `positionals[0]` is `string | undefined` and
  `previews[0]` is `SelectorMatchPreview | undefined` in the tests. Narrow with explicit
  `if (x === undefined)` guards or `expect(x).toBeDefined()` followed by a narrowing check.
  Never cast with `!` and never relax a `compilerOption`. If a strictness flag genuinely
  blocks the specified design, report **Blocked / unclear**.

- **`npm run --silent` does not suppress the banner in this environment.** Same risk as 2.1.
  If it fails, report **Blocked / unclear**; note that all contract-form (`npx tsx`)
  criteria pass. Do not add `.npmrc`, do not set `loglevel`, do not bake `--silent` into the
  script value, do not add banner-stripping code.

- **The tools suite count drifts.** `plans/2.1.md` asserted "10 passed"; this task raises it
  to 22. If the Builder sees a number other than 22, the cause is either a missing test or
  an accidentally added one — do not adjust the acceptance criterion, fix the test file.

- **Scope creep toward Task 2.3.** A tool that also runs the test is 2.3's job. If the
  Builder finds itself importing `node:fs` or `node:child_process`, it has left this task.

- **Scope creep toward "helpfulness".** Returning a *suggested* selector, a similarity
  score, or a ranked list of alternatives would move judgment out of the model and into an
  untested heuristic, and would let a fix be proposed without the verification gate seeing
  it. `query_selector` reports what is; it never recommends.
