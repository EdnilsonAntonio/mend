# Plan: 7.1 — Metrics

## Goal

After this task, a single command — `npm run metrics` — reads the already-persisted
`test_runs` / `heal_attempts` data out of PostgreSQL and prints (or emits as JSON) four
evidence numbers with their denominators: **heal rate**, **average tool calls**, **cost per
heal**, and **false-fix rate**. Every number is derived from stored rows and stored `jsonb`
transcripts — nothing is counted by hand, nothing is recomputed by re-running the agent, and
nothing new is written to the database. The false-fix number is an *audit*: it re-checks each
persisted attempt that claims a fix against the stored evidence that the fix was actually
executed, passed, and did not weaken an assertion. If that audit finds anything, the command
exits non-zero, so "false-fix rate must be 0" is enforced by the command rather than asserted
in prose.

## Open questions — answer before the Builder starts

These two are genuine design choices that the spec does not settle. Both have a recommended
default below; the rest of this plan is written assuming the recommendation is accepted. If
the human picks differently, the affected sections must be re-planned, not improvised.

### Q1. What counts as a "false fix"?

`spec/TASKS.md` says "false-fix rate (must be 0)" and defines it nowhere else.
`spec/REQUIREMENTS.md` and `spec/DESIGN.md` never use the term.

* **Option A (recommended) — evidence audit.** A false fix is a persisted attempt that
  *claims* a fix (`proposed_selector IS NOT NULL`) but whose own stored transcript does not
  contain the evidence the design requires: a `run_single_test` call for that exact selector
  that executed, passed, and recorded no assertion-integrity violation; plus the row-level
  invariants (`pr_url` only on `healed`/`high`, `tool_call_count <= 5`, status/confidence
  agreement). Fully computable from stored data. This is a direct measurement of the project's
  headline claim: *no fix was ever accepted without execution-based verification.*
* **Option B — semantic correctness.** A false fix is a fix that passed but targets the wrong
  element. This is **not computable from the current schema**: there is no human label column
  and no ground-truth column. Implementing it would require a new table and a human labelling
  workflow, which is a new feature, not Task 7.1.
* **Option C — partial ground truth via the seeded scenarios.** `agent/loop/scenario-matrix.ts`
  already encodes, per spec file, whether a fix is supposed to exist at all (scenario 5:
  `requiredOutcome: 'no-fix'`). A verified fix for a spec whose required outcome is `no-fix`
  is unambiguously a false fix.

**Recommendation: A + C.** Option A is the general rule; option C adds the one piece of real
ground truth the repository already has, scoped explicitly to the seeded demo spec files.
Option B is out of scope and is listed as such below.

### Q2. Where do token prices come from for cost-per-heal?

Token usage **is** already captured: `ModelUsage` (`promptTokens` / `completionTokens` /
`totalTokens`) is recorded per model round trip in `HealTranscript.modelRequests[].usage`
(see `agent/loop/types.ts` and `agent/loop/heal-loop.ts`), and the persisted transcript
envelope keeps `modelRequests` even when it is truncated. The model id is stored at
`transcript ->> 'model'`. So **tokens are stored; dollars are not**, and there is no price
table anywhere in the repository and no `cost` column in `DESIGN.md`'s schema.

* **Option A (recommended) — checked-in price table.** A small constant
  `MODEL_PRICING` in `metrics/pricing.ts`, keyed by model id, each entry carrying an explicit
  `source` string naming where the price came from and when it was checked. Unknown model ids
  are reported by name under `unpricedModels` and excluded from the dollar total, never
  silently priced at zero.
* **Option B — a new `cost_usd` column** written at heal time. Requires a migration and a
  change to `runner/heal-run.ts`, i.e. reopening Phase 4. Rejected: Task 7.1 is a read-side
  task.
* **Option C — report tokens only, no dollars.** Safest, but does not deliver "cost per heal".

**Recommendation: A**, with the seed entry `gpt-4o-mini` (the value of `DEFAULT_HEAL_MODEL`)
at **$0.15 per 1M input tokens / $0.60 per 1M output tokens**, `source: 'OpenAI public API
pricing, recorded 2026-09-14'`. **The human must confirm these two numbers are acceptable to
check in.** If they are not, take Option C and drop the two USD fields — the rest of the plan
is unchanged.

## Implementation steps

### 1. `metrics/types.ts`

Create the file with exactly the type block above and no runtime code. It must contain no
`import` statements.

### 2. `metrics/pricing.ts`

1. Define `ModelPrice` (re-declared locally here, not in `types.ts`) and export it.
2. `MODEL_PRICING` contains exactly one entry:
   ```ts
   export const MODEL_PRICING: Readonly<Record<string, ModelPrice>> = {
     'gpt-4o-mini': {
       inputUsdPerMillionTokens: 0.15,
       outputUsdPerMillionTokens: 0.6,
       source: 'OpenAI public API pricing, recorded 2026-09-14',
     },
   };
   ```
3. `normaliseModelId(model)`: `model.trim().toLowerCase().replace(/-\d{4}-\d{2}-\d{2}$/, '')`.
4. `lookupModelPrice(model)`: return `null` if `model === null` or `model.trim() === ''`;
   otherwise `MODEL_PRICING[normaliseModelId(model)] ?? null`.
5. `costUsd(price, promptTokens, completionTokens)`: clamp each token count with
   `Math.max(0, n)`, then
   `(p / 1_000_000) * price.inputUsdPerMillionTokens + (c / 1_000_000) * price.outputUsdPerMillionTokens`.
   Return unrounded.

### 3. `metrics/query.ts` — the SQL

`METRICS_ATTEMPTS_SQL` must be this string, verbatim:

```sql
SELECT
  a.id::text                                             AS id,
  a.test_run_id::text                                    AS test_run_id,
  a.spec_file                                            AS spec_file,
  a.test_name                                            AS test_name,
  a.original_selector                                    AS original_selector,
  a.proposed_selector                                    AS proposed_selector,
  a.confidence::text                                     AS confidence,
  a.tool_call_count                                      AS tool_call_count,
  a.status::text                                         AS status,
  a.failure_reason                                       AS failure_reason,
  a.pr_url                                               AS pr_url,
  a.created_at                                           AS created_at,
  a.transcript ->> 'model'                               AS transcript_model,
  a.transcript ->> 'outcome'                             AS transcript_outcome,
  a.transcript ->> 'confidence'                          AS transcript_confidence,
  a.transcript ->> 'proposedSelector'                    AS transcript_proposed_selector,
  a.transcript ->> 'truncated'                           AS transcript_truncated,
  jsonb_typeof(a.transcript -> 'verification')           AS verification_type,
  a.transcript -> 'verification' ->> 'passed'            AS verification_passed,
  a.transcript -> 'verification' ->> 'executed'          AS verification_executed,
  a.transcript -> 'verification' ->> 'rejected'          AS verification_rejected,
  a.transcript -> 'verification' ->> 'candidateSelector' AS verification_candidate,
  COALESCE((
    SELECT jsonb_agg(jsonb_build_object(
      'candidate',      tc -> 'result' ->> 'candidate',
      'passed',         tc -> 'result' -> 'passed',
      'executed',       tc -> 'result' -> 'executed',
      'rejected',       tc -> 'result' ->> 'rejected',
      'violationCount', CASE
                          WHEN jsonb_typeof(tc -> 'result' -> 'violations') = 'array'
                          THEN jsonb_array_length(tc -> 'result' -> 'violations')
                          ELSE 0
                        END
    ))
    FROM jsonb_array_elements(
      CASE WHEN jsonb_typeof(a.transcript -> 'transcript' -> 'toolCalls') = 'array'
           THEN a.transcript -> 'transcript' -> 'toolCalls'
           ELSE '[]'::jsonb END
    ) AS tc
    WHERE tc -> 'result' ->> 'kind' = 'run-single-test'
  ), '[]'::jsonb)                                        AS run_test_calls,
  COALESCE((
    SELECT jsonb_agg(jsonb_build_object(
      'promptTokens',     mr -> 'usage' -> 'promptTokens',
      'completionTokens', mr -> 'usage' -> 'completionTokens',
      'totalTokens',      mr -> 'usage' -> 'totalTokens'
    ))
    FROM jsonb_array_elements(
      CASE WHEN jsonb_typeof(a.transcript -> 'transcript' -> 'modelRequests') = 'array'
           THEN a.transcript -> 'transcript' -> 'modelRequests'
           ELSE '[]'::jsonb END
    ) AS mr
  ), '[]'::jsonb)                                        AS model_usages
FROM heal_attempts a
WHERE ($1::uuid IS NULL OR a.test_run_id = $1::uuid)
  AND ($2::timestamptz IS NULL OR a.created_at >= $2::timestamptz)
ORDER BY a.created_at ASC, a.id ASC
```

Notes the Builder must respect:
* This is the **only** statement in the module. No `INSERT`, `UPDATE`, `DELETE`, or DDL
  anywhere under `metrics/`.
* Parameters are always passed as a two-element array `[scope.testRunId, scope.since]`; both
  may be `null`.
* Never string-interpolate `scope` values into the SQL.

### 4. `metrics/query.ts` — mapping

Write small private helpers (not exported):

* `readString(raw, key): string` — throws `MetricsQueryError` unless `typeof === 'string'`.
* `readNullableString(raw, key): string | null` — `null` when value is `null` or `undefined`;
  otherwise `String(value)`.
* `readInt(raw, key): number` — accepts `number` or numeric `string`; throws unless finite.
* `readBooleanText(value: unknown): boolean | null` — `'true'`/`true` → `true`,
  `'false'`/`false` → `false`, anything else → `null`.
* `readIso(raw, key): string` — `Date` → `.toISOString()`, else `String(value)`.

Then `toMetricsAttemptRow(raw)`:

1. Map the plain columns with the helpers above.
2. `confidence`: throw unless the value is one of `'high' | 'low' | 'none'`.
3. `status`: throw unless one of `'investigating' | 'healed' | 'needs_review' | 'failed'`.
4. `transcriptConfidence`: `null` unless the value is one of the three confidence strings.
5. `transcriptTruncated`: `readBooleanText(raw.transcript_truncated) === true`.
6. `verificationPresent`: `raw.verification_type === 'object'`.
7. `verificationPassed` / `verificationExecuted`: `readBooleanText` of the respective column.
8. `verificationRejected` / `verificationCandidate`: `readNullableString`.
9. `runTestCalls`: `raw.run_test_calls` arrives already parsed as a JS array (pg parses
   `jsonb`). If it is not an array, use `[]`. Map each element to `RunTestCallRecord`:
   `candidate` via nullable-string, `passed`/`executed` via a boolean-or-null check,
   `rejected` via nullable-string, `violationCount` via `Number(...)` defaulting to `0` when
   not finite.
10. `modelUsages`: same treatment; each field is `typeof v === 'number' && Number.isFinite(v)
    ? v : null`.

`loadMetricsRows(read, scope)`:
```ts
const rows = await read(METRICS_ATTEMPTS_SQL, [scope.testRunId, scope.since]);
return rows.map(toMetricsAttemptRow);
```

`createPgRowReader(connectionString, schema)`: call `connectRunClient` from
`../db/repository.js`; return
```ts
{
  read: async (text, values) => (await client.query(text, values as unknown[])).rows,
  close: async () => { await client.end(); },
}
```

### 5. `metrics/compute.ts` — foundations

1. `import { TOOL_CALL_COUNT_CEILING } from '../db/schema-contract.js';` and
   `export const TOOL_CALL_CAP = TOOL_CALL_COUNT_CEILING;`. Do not write `5` anywhere in this
   module.
2. `import { PR_DELIVERY_FAILURE_REASON_PREFIX } from '../db/repository.js';`
3. `import { SCENARIO_EXPECTATIONS } from '../agent/loop/scenario-matrix.js';`
4. `isSettled(row)` → `row.status !== 'investigating'`.
5. `hasVerifiedFix(row)` → `isSettled(row) && row.proposedSelector !== null`.
6. `isPrDeliveryFailure(row)` → `row.status === 'needs_review' && row.failureReason !== null
   && row.failureReason.startsWith(PR_DELIVERY_FAILURE_REASON_PREFIX)`.
7. Private `round(value: number, dp: number): number` →
   `Number(value.toFixed(dp))`.
8. `rate(n, d, dp)` → `d === 0 ? null : round(n / d, dp)`.

### 6. `computeCounts`

Single pass over `rows`. `testRuns` is the size of a `Set` of `testRunId` over **all** rows
(settled or not). `withProposedFix` counts settled rows with `proposedSelector !== null`.
`withPrUrl` counts rows with `prUrl !== null`. `prDeliveryFailures` uses `isPrDeliveryFailure`.

### 7. `computeHealRate`

Denominator is **settled**, never `rows.length`. `healed` = settled rows with
`status === 'healed'`. `verifiedFixes` = settled rows with `status === 'healed' ||
status === 'needs_review'`. Both rates rounded to 4 dp via `rate(..., 4)`.

A PR-delivery failure is persisted as `needs_review`, so it counts toward `verifiedFixes`, not
`healed`. This is deliberate: the metric reports what the database says, and the separate
`counts.prDeliveryFailures` number explains the gap.

### 8. `computeToolCalls`

Over settled rows only.
* `settledMean` / `healedMean` / `verifiedFixMean`: arithmetic mean of `toolCallCount` over
  the settled / `status === 'healed'` / `hasVerifiedFix` subsets, rounded to 2 dp, `null` when
  the subset is empty.
* `max`: maximum `toolCallCount` over settled rows, `null` when there are none.
* `capReachedCount`: settled rows with `toolCallCount === TOOL_CALL_CAP`.
* `distribution`: initialise keys `'0'` through `String(TOOL_CALL_CAP)` to `0`, then increment
  `String(row.toolCallCount)` when that key already exists; ignore out-of-range values (they
  are separately reported as a false-fix finding).

### 9. `computeCost`

Over settled rows only.
1. For each row, sum `promptTokens` and `completionTokens` across `row.modelUsages`, treating
   `null` as `0`. Track `rowHasUsage` = at least one usage entry had a non-null
   `promptTokens` or `completionTokens`.
2. Accumulate `promptTokens`, `completionTokens` globally. `totalTokens` is the sum of the two
   accumulators (do **not** trust the stored `totalTokens`; it is reported per turn and may be
   absent).
3. `price = lookupModelPrice(row.transcriptModel)`. If `rowHasUsage && price !== null`,
   add `costUsd(price, rowPrompt, rowCompletion)` to a running total and increment
   `attemptsWithPricedModel`. If `rowHasUsage && price === null`, add
   `row.transcriptModel === null ? '(unknown)' : normaliseModelId(row.transcriptModel)` to a
   `Set` of unpriced model ids.
4. `totalCostUsd` = `attemptsWithPricedModel === 0 ? null : round(total, 6)`.
5. `costPerAttemptUsd` = `null` when `totalCostUsd === null` or `attemptsConsidered === 0`,
   else `round(totalCostUsd / attemptsConsidered, 6)`.
6. `costPerHealedUsd` = `null` when `totalCostUsd === null` or the healed count is `0`, else
   `round(totalCostUsd / healedCount, 6)`, where `healedCount` is settled rows with
   `status === 'healed'`. **The numerator is the total cost of all settled attempts, including
   the ones that failed** — cost per heal means what a successful heal costs in practice.
   State this in the README.
7. `unpricedModels` = sorted array from the Set. `complete` = `usageCoverage === 1 &&
   unpricedModels.length === 0`.

### 10. `auditFalseFixes` — the false-fix rule set

Iterate settled rows in input order (already ordered by `created_at ASC, id ASC`). Push
findings in the order the rules appear below. `detail` is a short one-line explanation that
names the offending values.

**Rules that apply only when `row.proposedSelector !== null`:**

| Code | Fires when |
| --- | --- |
| `fix-without-verification` | `row.verificationPresent === false` |
| `fix-without-passing-verification` | `row.verificationPresent === true && row.verificationPassed !== true` |
| `fix-without-matching-passing-run` | no element of `row.runTestCalls` satisfies `candidate === row.proposedSelector && passed === true && executed === true` |
| `fix-with-integrity-violation` | some element of `row.runTestCalls` with `candidate === row.proposedSelector` has `rejected !== null || violationCount > 0` |
| `transcript-selector-mismatch` | `row.transcriptProposedSelector !== row.proposedSelector` |
| `fix-for-unfixable-scenario` | `lookupScenario(row.specFile)?.requiredOutcome === 'no-fix'` |

**Rules that apply to every settled row:**

| Code | Fires when |
| --- | --- |
| `healed-without-high-transcript-confidence` | `row.status === 'healed' && row.transcriptConfidence !== 'high'` |
| `pr-url-without-healed-high` | `row.prUrl !== null && !(row.status === 'healed' && row.confidence === 'high')` |
| `tool-call-cap-exceeded` | `row.toolCallCount > TOOL_CALL_CAP` |
| `status-confidence-mismatch` | the `(status, confidence)` pair is not one of `healed/high`, `needs_review/low`, `failed/none` |

**Deliberate non-rule — do not add it.** A PR-delivery failure is persisted as
`needs_review`/`low` while its transcript still records `confidence: 'high'` (see
`toDeliveryFailureSettleInput` in `db/repository.ts`). A rule comparing
`row.confidence` with `row.transcriptConfidence` would flag every such row as a false fix.
The rule set above deliberately compares transcript confidence only for `healed` rows.

`lookupScenario(specFile)` is a private helper: normalise both sides by replacing `\` with
`/` and stripping a leading `./`, then find the `SCENARIO_EXPECTATIONS` entry whose `specFile`
matches. Returns `undefined` when there is no match (i.e. the tool is running against a
repository other than the demo one), in which case the scenario rule simply never fires.

`falseFixes` counts **distinct attempt ids** that produced at least one finding.
`claimedFixes` counts settled rows with `proposedSelector !== null`.
`falseFixRate = rate(falseFixes, claimedFixes, 4)`.

### 11. `computeScenarios`

For each entry in `SCENARIO_EXPECTATIONS`, gather settled rows whose spec file matches
(same normalisation as above). Skip entries with zero matching rows. For each kept entry:
* `attempts` / `healed` / `needsReview` / `failed` are straight counts.
* `missed` = when `requiredOutcome === 'healed'`, the count of matching rows with
  `proposedSelector === null`; otherwise `0`.
* `falseFixes` = when `requiredOutcome === 'no-fix'`, the count of matching rows with
  `proposedSelector !== null`; otherwise `0`.

Return in ascending `scenario` order.

### 13. `metrics/format.ts`

scope: run=<testRunId or "all"> since=<since or "all">

## Risks

1. **"False-fix rate" is under-specified in the spec (highest risk).** See Q1. If the human
   has a different definition in mind, the entire `auditFalseFixes` rule table is wrong and the
   headline number means something else. **Builder: do not start step 10 until Q1 is answered.**
   If you find yourself inventing an eleventh rule, stop and report "Blocked / unclear".
2. **Checking in dollar prices (Q2).** Model prices change and a stale table silently produces
   wrong dollar figures. Mitigation: every price carries a `source` string, the report prints
   it, and an unknown model is reported by name rather than priced at zero. If the human
   declines to check in prices, drop `totalCostUsd`, `costPerAttemptUsd`, and
   `costPerHealedUsd` from `CostSection` and report tokens only — everything else stands.
3. **Usage may be absent in existing rows.** Fake-model test runs and any turn where the
   OpenAI response omitted `usage` store `usage: null`. If most stored attempts predate real
   API use, `usageCoverage` will be low and `totalCostUsd` will be misleadingly small. The
   `complete` flag and the `[PARTIAL]` line exist precisely for this. Do not silently treat a
   missing usage as zero cost without the `[PARTIAL]` marker.
4. **The PR-delivery-failure row shape is a trap.** `toDeliveryFailureSettleInput` persists
   `needs_review`/`low` while leaving `confidence: 'high'` inside the transcript. A naive
   "row confidence must equal transcript confidence" audit rule would report a false positive
   and make the command exit 5 on a perfectly healthy database. The rule table above
   deliberately omits that comparison — do not add it back.
5. **`investigating` rows.** They carry `transcript = '{}'`, `confidence = 'none'`, and
   `tool_call_count = 0` by default. Including them in any denominator would understate the
   heal rate and including their `0` in the tool-call mean would understate it too. Every
   aggregate except `counts.attempts`, `counts.stranded`, and `counts.testRuns` filters them
   out via `isSettled`. If the integration test shows a stranded row affecting a rate, the
   filter is missing somewhere.
6. **Transcript truncation.** `serialiseTranscript` clamps strings to 4,000 characters when a
   transcript exceeds 2 MB. A selector longer than 4,000 characters would be mutated and
   trip `transcript-selector-mismatch` or `fix-without-matching-passing-run` as a false
   positive. This is vanishingly unlikely for real selectors; `transcriptTruncated` is carried
   on the row so a human can recognise the case. Do not add a special case unless it actually
   fires.
7. **`jsonb_array_elements` on a non-array errors.** The `CASE WHEN jsonb_typeof(...) =
   'array'` guards in the SQL are not decoration — a malformed transcript without them takes
   down the whole query. Keep them. Verify with the `investigating` row in the integration
   test, whose transcript is `{}`.
8. **`SCENARIO_EXPECTATIONS` couples metrics to the demo repository.** `scenario-matrix.ts`
   imports `Page` from `@playwright/test` as a **type-only** import, so importing
   `SCENARIO_EXPECTATIONS` pulls in no browser runtime. If the import turns out to drag in
   Playwright at runtime, stop and report it rather than copying the table — a duplicated
   expectation table would drift.
9. **The integration test needs a real database.** It must skip cleanly, not fail, when
   `MEND_TEST_DATABASE_URL` is unset — otherwise `npm run test:metrics` fails on any machine
   without PostgreSQL. Copy the skip guard from
   `db/__tests__/repository.integration.spec.ts` exactly.
10. **Exit code 5 is a real gate.** If `npm run metrics` starts exiting 5 on a database the
    team believes is clean, the correct response is to read the printed findings and fix the
    agent — not to relax the audit rule. Any change that loosens a rule to get a green exit is
    a failure of this task, not a fix.
