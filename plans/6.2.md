# Plan: 6.2 — Detail view

## Goal

After this task the dashboard has a second route, `/attempts/[id]`, that replays one heal
investigation in full: the DOM the agent saw, every selector it tried with the match count that
came back, the verification run (`run_single_test`) with its assertion-integrity result, its spec
diff and its raw test output, the confidence signals that produced the verdict, and every model
turn. It is a Server Component reading PostgreSQL directly — same stack, same conventions, same
read-only guarantee as Task 6.1 — and it is the first and only place the `transcript` `jsonb`
column is selected. Every section renders for **every** attempt: a `failed` or `investigating`
attempt shows the same section headings as a `healed` one, filled with an explicit sentence
saying what is absent and why, so a failed attempt is exactly as legible as a successful one. The
list view's attempt-id cell becomes a link into this page. Nothing is editable, nothing is
re-runnable, no metric is computed, and the stored `status`/`confidence` columns remain the
authoritative verdict even when the transcript envelope disagrees with them.

---

## Read this before you start: the seven ways to ruin this task

**1. Rendering stored HTML as HTML.** The DOM snapshot is attacker-shaped input from the page
under test. It is rendered as **text**, inside `<pre>`, always. The string
`dangerouslySetInnerHTML` must not appear anywhere under `dashboard/`. No `innerHTML`, no
`<iframe srcdoc>`, no sanitiser library, no HTML preview pane.

**2. Writing to the database.** Same rule as 6.1, checked the same way: no `INSERT`, `UPDATE`,
`DELETE`, `TRUNCATE`, `DROP`, `ALTER`, `CREATE`, `GRANT` anywhere under `dashboard/lib/` or
`dashboard/app/` — including in comments and in UI prose, because the Reviewer's grep is
case-insensitive and does not know the difference. Write "removed", "cleared", or "reduced"
rather than "dropped"/"deleted"; write "recorded" rather than "updated".

**3. Modifying `dashboard/lib/attempts.ts` or `dashboard/lib/db.ts`.** Both are finished. The
detail path imports `RowReader`, `DashboardDataError`, and `toHealAttemptListRow` from
`attempts.ts` and `getRowReader` from `db.ts` and adds nothing to either.
`git diff HEAD --name-only -- dashboard/lib/attempts.ts dashboard/lib/db.ts` must print nothing.
In particular do **not** add `transcript` to `LIST_ATTEMPTS_SQL`.

**4. Touching anything outside `dashboard/` and `db/README.md`.** At the end of this task
`git diff HEAD --name-only -- agent/ runner/ tests/ app-under-test/ breakage/ db/migrations/ spec/ db/repository.ts db/client.ts db/migrate.ts db/transcript.ts db/schema-contract.ts package.json tsconfig.json .gitignore`
must print nothing. No migration, no index, no new npm dependency, no root script. The root
`tsconfig.json` already includes `dashboard/lib/**/*.ts` and `dashboard/__tests__/**/*.ts`, and
`playwright.dashboard.config.ts` already points at `dashboard/__tests__` — nothing needs wiring.

**5. Computing metrics.** Heal rate, percentages, averages, cost, false-fix rate are **Task
7.1**. This page shows one attempt's own recorded numbers and nothing derived across attempts.
No `%` in any computed value. No aggregate query.

**6. Adding interactivity.** No `'use client'`, no `useState`, no `onClick`, no `fetch(`, no
`<form>`, no button that does anything. `REQUIREMENTS.md`: the dashboard is read-only, and the
tool never merges. There is no approve, reject, retry, re-run, or "apply fix" affordance, not
even a disabled one.

**7. Believing the transcript over the columns.** `db/repository.ts`'s
`toDeliveryFailureSettleInput` settles a row as `needs_review`/`low` while **preserving** a
transcript envelope that still records `confidence: 'high'` (see `db/README.md`, "PR delivery
functions"). The badges on this page come from the row columns. The envelope's own
`confidence`/`status` are shown as *what the gate decided at the time*, and a mismatch is called
out explicitly. Never render the envelope's confidence as the attempt's confidence.

### Q2 — Is the raw `transcript.messages` conversation rendered?

`HealTranscript.messages` is the full OpenAI conversation. It embeds the DOM snapshot a second

| Option | Trade-off |
| --- | --- |

## Architectural decisions already made (do not revisit)

1. **The normaliser is lossless; components clamp.** `dashboard/lib/transcript.ts` converts the
   `unknown` jsonb value into typed view objects and truncates **nothing**. Every render cap
   (`MAX_SNAPSHOT_RENDER_CHARS`, etc.) is applied in the `.tsx` components, and every clamp is
   visible in the output as a "showing the first N of M characters" note. This keeps the whole
   normaliser unit-testable without React, and keeps truncation honest.

2. **The normaliser never throws and never rejects a row.** A malformed, partial, truncated, or
   entirely foreign transcript degrades to `{ kind: 'unrecognised' }` or to per-step
   `{ kind: 'unknown' }` — it never turns into a 500 and never hides the rest of the page. This
   is the opposite of `toHealAttemptListRow`'s strictness, on purpose: the columns are a schema,
   the jsonb is a payload.

3. **Every section always renders.** Missing data produces a sentence, never a disappearing
   heading. This is the mechanism by which "failed attempts are as legible as successful ones" is
   made literally checkable: the set of `data-testid="detail-*"` sections is identical for a
   `healed` attempt and a `failed` one.

4. **One query per page load, bounded by `LIMIT 1` and a primary-key lookup.** No count query, no
   join, no retry, no cache, no `revalidate`.

5. **The attempt id is validated before it reaches SQL.** A non-UUID path segment returns
   `invalid-id` without issuing a query. This is not primarily about injection (the query is
   parameterised) but about not turning a typo in the URL bar into a `query-failed` panel
   containing a PostgreSQL type error.

6. **Enum and cap literals are re-declared locally, with a source-of-truth comment**, exactly as
   `dashboard/lib/types.ts` already does. The dashboard build must not depend on the agent module
   graph.

7. **No `'use client'`, no `<details>`, no JavaScript.** Long blocks are `<pre>` elements with a
   CSS `max-height` and `overflow: auto`. Everything is present in the served HTML.

### 1. `dashboard/lib/format.ts` — MODIFY, additive only

Append the following. Imports may grow by `import type { HealStatus } from './types';` — which is
already imported — nothing else.

```ts
export interface ClampedText {
  readonly text: string;
  readonly clamped: boolean;
  readonly originalLength: number;
}
```

- `clampForDisplay(text: string, maxChars: number): ClampedText`
  - `maxChars < 1` → `{ text: '', clamped: text.length > 0, originalLength: text.length }`
  - `text.length <= maxChars` → `{ text, clamped: false, originalLength: text.length }`
  - otherwise → `{ text: text.slice(0, maxChars), clamped: true, originalLength: text.length }`
  - **No ellipsis is appended.** The UI renders an explicit count instead.
- `toolLabel(tool: string): string` — `Record<string, string>` lookup over exactly
  `get_dom_snapshot` → `'DOM snapshot'`, `query_selector` → `'Query selector'`,
  `run_single_test` → `'Run single test'`; anything else returns `tool` verbatim. Never throws,
  including for `''`.
- `formatDuration(ms: number | null): string` — `null`, `NaN`, or `< 0` → `EMPTY_CELL`;
  `< 1000` → `` `${Math.round(ms)}ms` ``; otherwise `` `${(ms / 1000).toFixed(1)}s` ``.
  No `Intl`, no locale API.
- `formatJson(value: unknown): string` —
  `try { return JSON.stringify(value, null, 2) ?? String(value); } catch { return '[unserialisable]'; }`
- `matchCountLabel(matchCount: number | null): string` — `null` → `'not measured'`; `0` →
  `'0 matches'`; `1` → `'1 match'`; otherwise `` `${matchCount} matches` ``.
- `booleanLabel(value: boolean | null): string` — `null` → `EMPTY_CELL`; `true` → `'yes'`;
  `false` → `'no'`.
- `noPrExplanation(status: HealStatus): string` — `Record<HealStatus, string>` lookup:
  - `healed` → `'No pull-request URL is recorded for this attempt.'`
  - `needs_review` → `'No pull request: low confidence routes to human review.'`
  - `failed` → `'No pull request: no verified fix was found.'`
  - `investigating` → `'No pull request: this attempt never settled.'`

**3b. Accessors** (exported; each is one expression, none throws):

- `asObject(value: unknown): Record<string, unknown> | null` — non-null, non-array `object` only.
- `asString(value: unknown): string | null` — `typeof value === 'string' ? value : null`.
- `asNumber(value: unknown): number | null` — `typeof value === 'number' && Number.isFinite(value) ? value : null`.
- `asBoolean(value: unknown): boolean | null` — `typeof value === 'boolean' ? value : null`.
- `asArray(value: unknown): readonly unknown[]` — `Array.isArray(value) ? value : []`.

**3c. `normaliseTranscript(raw: unknown): TranscriptView`.** In this order:

1. If `typeof raw === 'string'`: attempt `JSON.parse(raw)` inside `try`; on success recurse
   **once** with the parsed value; on failure return `{ kind: 'unrecognised', json: raw }`.
   (`pg` returns `jsonb` already parsed, but a custom type parser must not produce a broken page.)
2. `const obj = asObject(raw);` if `obj === null` or `Object.keys(obj).length === 0` return
   `{ kind: 'absent' }`.
3. `const inner = asObject(obj.transcript);` if `inner === null` return
   `{ kind: 'unrecognised', json: formatJson(raw) }`.
4. Otherwise return the `TranscriptEnvelopeView`, field by field:
   - `kind: 'envelope'`
   - `schemaVersion: asNumber(obj.schemaVersion)`
   - `truncated: asBoolean(obj.truncated) ?? false`
   - `outcome`, `stopReason`, `recordedConfidence` (from `obj.confidence`), `recordedStatus` (from
     `obj.status`), `failureReason`, `proposedSelector`, `originalSelector`, `model`, `startedAt`,
     `errorMessage` — each `asString(...)`
   - `prEligible: asBoolean(obj.prEligible)`, `capReached: asBoolean(obj.capReached)`
   - `reasons: asStringArray(obj.reasons)`
   - `toolCallCount: asNumber(obj.toolCallCount)`, `modelTurnCount: asNumber(obj.modelTurnCount)`,
     `durationMs: asNumber(obj.durationMs)`
   - `verification: normaliseVerification(obj.verification)`
   - `measurement: normaliseMeasurement(obj.measurement)`
   - `signals: normaliseSignals(obj.signals)`
   - `bootstrapSnapshot: normaliseDomSnapshot(inner.bootstrapSnapshot)`
   - `bootstrapSpecSource: asString(inner.bootstrapSpecSource)`
   - `messageCount: asArray(inner.messages).length`
   - `steps: asArray(inner.toolCalls).map(normaliseStep)` — `normaliseStep(value, position)`
   - `modelTurns: asArray(inner.modelRequests).map(normaliseModelTurn)`

- `normaliseDomSnapshot(value: unknown): DomSnapshotView | null` — `null` when

**4e. `loadAttemptDetail(read: RowReader | null, id: string): Promise<AttemptDetailLoad>`.**

```
if (read === null) → { ok:false, code:'no-database-url', message:'DATABASE_URL is not set.', attemptId:id }
if (!isAttemptId(id)) → { ok:false, code:'invalid-id', message:'Not a valid heal attempt id.', attemptId:id }
try {
  const row = await getHealAttempt(read, id);
  if (row === null) → { ok:false, code:'not-found', message:'No heal attempt with that id.', attemptId:id }
  return { ok:true, row, transcript: normaliseTranscript(row.transcript) };
} catch (error) {
  const raw = error instanceof Error ? error.message : String(error);
  return { ok:false, code:'query-failed', message: redactConnectionUrls(raw), attemptId:id };
}
```

The `invalid-id` branch must return **before** any call to `read`. No retry, no fallback query,
no second lookup by prefix. `message` never interpolates `id`.

## Risks

**`params` is a Promise.** In Next 15+ (installed: `next@^16.3.4`) dynamic route params are
async. The synchronous `{ params }: { params: { id: string } }` signature is a type error and
fails `next build`. If the build reports a params type mismatch, that is the cause — await it, do
not cast it to `any` and do not downgrade Next.

**The case-insensitive write-verb grep tripping on prose.** `\b(insert|update|delete|truncate|drop|alter|grant)\b`
runs over comments and JSX text in `dashboard/lib` and `dashboard/app`. Words like "updated",
"dropped", or "deleted" in a user-facing sentence will fail the check even though the code writes
nothing. Use "recorded", "reduced", "cleared", "removed" instead. (`created_at` is safe: the `\b`
after `create` does not match.)

**`pg` may return `jsonb` as a string.** By default `pg` parses `jsonb` into a JS value, so
`row.transcript` is an object. A custom type parser elsewhere in the process would make it a
string. Step 3c's one-shot `JSON.parse` branch handles it. Do not remove it, and do not "simplify"
`normaliseTranscript` to assume an object.

**Root `noUncheckedIndexedAccess`, `noUnusedLocals`, `noUnusedParameters`.** These apply to
`dashboard/lib/**` and `dashboard/__tests__/**` via the root `tsconfig.json` but **not** to
`dashboard/app/**` (which only the dashboard's own `tsc` sees). Code that compiles in a component
may fail at the root when moved into `lib/`. `rows[0]` is `| undefined` — guard it. Remove every
unused import.

**Two TypeScript versions.** Root is `typescript@^7`, dashboard is `^5.9`. `dashboard/lib/**/*.ts`
is compiled by both. If a construct is accepted by one and rejected by the other, simplify until
both accept it — no `// @ts-expect-error`, no `any`, no version change.

**A huge DOM snapshot making the page unusable.** `get_dom_snapshot` is token-bounded (Task 2.1)
so the ordinary case is small, but a truncated transcript can still carry a 4 000-character clamped
string per field and an unrecognised envelope can carry anything. `ClampedBlock` plus the
`.block { max-height; overflow: auto }` rule are the two defences. If a page still feels
unusable, report it rather than raising the caps.

**The integration fixture failing `assertConfidenceInvariant`.** `assessHealResult` throws if a
`high` fixture is not internally consistent (verified, non-null selector, `verification.passed`,
measurement `matchCount === 1`, `toolCallCount <= 2`). If it throws, the **fixture** is wrong, not
the invariant. Do not weaken the fixture into `low` to make the test pass — assertion 5 depends on
a genuine `high` row. Never modify `agent/loop/confidence.ts`.

**The migration's CHECK constraints rejecting a fixture insert.** The only legal
`(status, confidence, proposed_selector)` shapes are `('investigating','none',NULL)`,
`('healed','high',<selector>)`, `('needs_review','low',<selector>)`, `('failed','none',NULL)`, and
`tool_call_count` must be `0..5`. If an insert is rejected, the fixture is wrong. Do not write a
migration.

**Enum drift.** `dashboard/lib/types.ts` re-declares the enums by design. If the integration suite
starts throwing `DashboardDataError` for a status, the correct fix is to add the value to
`HEAL_STATUS_VALUES`, never to loosen `toHealAttemptListRow`.

**Superseded 6.1 criterion.** `plans/6.1.md` asserts
`grep -rn "href=\"/attempts\|<Link" dashboard/app` prints nothing. Task 6.2 deliberately makes
that grep match (Q3). Every other 6.1 criterion still holds and the Reviewer should still check
them.

**Temptation to show a heal rate on the detail page.** One attempt has no rate. Any aggregate is
Task 7.1, which must derive it from stored data in one reproducible command; a second,
differently-computed number would contradict it.

**Temptation to make the transcript "prettier" by trusting it.** The envelope is stored data from
a possibly-older schema version, possibly reduced by the 2 MB guard. Every field is optional at
runtime. A single non-defensive `.map` on a field that turned out to be `null` takes the whole
page down — which is exactly the failure mode Task 6.1 spent an architectural decision avoiding.
