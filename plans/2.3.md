# Plan: 2.3 — `run_single_test` with assertion-integrity check

> TASKS.md calls this "the highest-value task in the project. Budget accordingly." This plan
> is correspondingly long. Nothing in it is optional.

---

## Revision after round-3 review

**Status: revised after three failed review rounds. Rounds 1 and 2 found real defects in the
code (a counting bug in the `string-literals` rule; a tautological assertion in test 21 and a
stray literal in the README) and those are fixed. Round 3 found a defect in *this plan*, not
in the code.**

**The gap.** Step 5 creates the root `mend-tmp/` directory with
`mkdir(join(REPO_ROOT, TEMP_ROOT_DIR_NAME), { recursive: true })`, and the `finally` block
removes only the per-call subdirectory (`rm(tempDir, { recursive: true, force: true })`). The
empty root `mend-tmp/` directory therefore survives every successful call. Three places in
this plan assumed the opposite: step 10's cleanliness command
(`test ! -d mend-tmp && echo "no mend-tmp left behind: OK"`), the "Purity, boundedness, and
safety" checkbox that repeated it, and the "Nothing else moved" checkbox "`mend-tmp/` does
not exist in the working tree at the end". Meanwhile tests 18, 21 and 22 already used the
correct, looser wording ("`mend-tmp` is absent or empty"), and the risk note "The temp
directory survives a crash" already forbade any sweep of the root. The plan contradicted
itself, and the implementation was measured against the wrong half of it.

**Resolution — option (b), with no change to the verification logic.** The root `mend-tmp/`
directory is a **durable, gitignored workspace directory**: created on demand, never removed.
Only the per-call `run-XXXXXX/` subdirectory is created and destroyed per call. This is now
architectural decision 16, and step 5, step 9 subsection 7, step 10 and every
acceptance-criteria checkbox that mentions `mend-tmp` are updated to agree with it.

**Why not option (a) (`rmdir` the root after each call, swallowing `ENOTEMPTY`/`ENOENT`).**
It is not actually race-free. Swallowing `ENOTEMPTY` protects a *populated* root, but there
is a window in every concurrent caller between its `mkdir(tempRootDir, { recursive: true })`
and its `mkdtemp(tempRootDir + '/run-')` during which the root is empty and therefore
removable — and that caller's `mkdtemp` then fails with `ENOENT`. Closing that window
requires a retry around `mkdtemp`, and decision 10 forbids retries anywhere in the
verification path. Trading a race in the verification gate for the cosmetic removal of an
empty gitignored directory is the wrong trade in this project. `mend-tmp/` sits beside
`test-results/`, `playwright-report/` and `blob-report/` in `.gitignore`; Playwright leaves
those behind too. Git does not track directories, so an empty `mend-tmp/` can never appear in
`git status --porcelain` — the "nothing else moved" guarantee is unaffected.

**Scope of this revision.** Decision 16 (new), step 5 item 5, step 9 subsection 7 (one
sentence added to the README requirement), step 10's "Cleanliness" block, one added
Documentation checkbox, three revised acceptance-criteria checkboxes, and two risk notes
cross-referencing decision 16. **Nothing else in this plan changes.** Everything else has
been through three review rounds and is not reopened.

## Goal

After this task the repository can answer, deterministically and with no OpenAI dependency,
the only question that matters in this project: **"if I swap this one selector, does the
real test actually pass?"** A candidate selector is substituted into a **temporary copy** of
a spec file — never the original — the proposed source is put through a rule-based
assertion-integrity gate that rejects any removal, weakening, skipping, or commenting-out of
an assertion **before a browser is ever launched**, and only then is the single named test
executed by a real `playwright test` child process. `passed` is derived from the child's
exit code plus its JSON report (exactly one test expected, zero unexpected, zero flaky, zero
skipped) — never from a claim. The original spec file is hashed before and after every call
and the call self-rejects if the hash moved. This is the third and last of the deterministic
tools, and like the first two it is built and proven before any model exists.

## Open questions — answer these at the approval gate

The plan below is written assuming the **recommended** option in each case. If the human
accepts the recommendations they become binding and the Builder makes no decision here. If
the human picks otherwise, this plan must be revised before the Builder is invoked.

### Q1 — Where does the temp spec copy live? → **Recommend B**

* **A.** A sibling of the original (`tests/login-submit.mend-verify-<id>.spec.ts`), with
  `playwright.config.ts` gaining a `testIgnore` so the baseline suite never picks it up.
  Preserves relative imports exactly.
* **B (recommended).** A fresh unique directory under a repo-root `mend-tmp/`
  (`mend-tmp/<uuid>/login-submit.spec.ts`), gitignored, removed in a `finally`, with a
  dedicated `playwright.verify.config.ts` whose `testDir` is that unique directory.

Rationale for B: it never writes a byte into `tests/`, so no crash can leave the baseline
suite reporting 6 tests, and `playwright.config.ts` stays byte-identical (A requires editing
the config that guards the 5/5 baseline — the one file this project can least afford to
destabilise). The cost of B is that a spec importing a *relative* helper (`../fixtures/x`)
would fail to resolve; all five baseline specs import only `@playwright/test`, so the cost
is zero today and is recorded as a documented v1 limitation. The directory is `mend-tmp`,
**not** `.mend-tmp`: a leading dot introduces a needless "does Playwright glob into hidden
directories" question, and this task has enough real risk already.

### Q2 — What are the CLI exit codes? → **Recommend B**

* **A.** Mirror Task 2.2 exactly: exit `0` whenever a structured result was produced,
  including `passed: false`.
* **B (recommended).** `0` = verification **passed**. `3` = a result was produced but
  verification did not pass (executed-and-failed, or rejected before execution). `2` = CLI
  usage error. `1` = infrastructure failure (spec unreadable at the process level, spawn
  failure).

Rationale for B: this is the verification gate. A shell doing
`run-single-test.cli.ts ... && mark_healed` must not mark a heal when the test failed, and
Task 2.2's convention was designed for a read-only inspector where "0 matches" is a normal
answer. Here "did not pass" is precisely the thing the exit code must not conflate with
success. The deviation from 2.2 is deliberate and is documented in the README.

### Q3 — Is `verifySpecSource` public? → **Recommend A**

* **A (recommended).** Yes. `verifySpecSource` is the single verification choke point
  (integrity gate → temp write → execute → hash re-check); `runSingleTest` is a thin wrapper
  that computes the proposed source by substitution and delegates to it. Both are exported.
* **B.** Keep the choke point private and only export `runSingleTest`.

Rationale for A: TASKS.md requires this task be "verified with a deliberately malicious diff
as a test case". With B, the only way to feed the gate a hostile *diff* end-to-end is a
mock, a monkeypatch, or a test-only backdoor — all worse. With A the hostile diff is passed
through the same code path production uses, which is exactly the assurance the criterion is
asking for. The mitigation for the extra surface is stated in decision 4 below: Phase 3
registers **only** `runSingleTest` as an OpenAI tool, and `verifySpecSource` runs the
integrity gate unconditionally, so it is not a bypass.

## Reconciliation note: input and result are supersets of DESIGN.md's

DESIGN.md's tool-contract table says `run_single_test` takes a "candidate selector" and
returns `{ passed, output }`.

* **Input.** A candidate selector alone is not sufficient to run anything — the tool also
  needs the spec file, the test title, and the selector being replaced. Those three come
  from the failure context, not from the model. `runSingleTest` therefore takes all four.
  **Phase 3 will bind `specFile`, `testName` and `originalSelector` from the classified
  failure and expose only `candidateSelector` in the JSON tool schema the model sees**, so
  DESIGN.md's contract is what the model actually experiences. That binding is Phase 3's
  job, not this task's.
* **Output.** `passed` and `output` are present verbatim. The additional fields
  (`executed`, `rejected`, `violations`, `exitCode`, `timedOut`, `durationMs`,
  `proposedSource`, `changedLines`) exist because TASKS.md's third and fourth acceptance
  criteria demand that a rejection be observably distinguishable from an execution failure
  ("rejected **before** execution"), and because Phase 4 stores the transcript and Phase 5
  commits the patched file.

This is addition, not contradiction, and it is recorded here so the Reviewer does not read
it as spec drift. `spec/DESIGN.md` is **not** edited by this task.

## Architectural decisions already made (do not revisit)

1. **Execution is a real `playwright test` child process.** Not an in-process Playwright
   API call, not a re-implementation of the test body. DESIGN.md's whole argument is that
   verification is real because Playwright actually runs. The child is spawned as
   `process.execPath` + the resolved `playwright/cli.js` path, so there is no dependency on
   `npx`, on shell resolution, or on `node_modules/.bin` layout.

2. **`passed` is computed from the JSON report, not from parsing human text.**
   `playwright.verify.config.ts` writes a JSON report to a per-call path.
   `passed === (exitCode === 0 && !timedOut && stats.expected === 1 && stats.unexpected === 0
   && stats.flaky === 0 && stats.skipped === 0)`. A run that matched zero tests, matched two
   tests, or was skipped is **not** a pass. Never grep `"1 passed"` out of stdout to decide
   this.

3. **The integrity gate runs before the temp file is written and before any process is
   spawned.** On violation the function returns with `executed: false` and never touches the
   filesystem beyond reading the original. This ordering is a hard requirement of TASKS.md
   ("rejected **before** execution") and is asserted by tests 20, 21 and 22 via
   `executed === false`.

4. **`verifySpecSource` is the single choke point; `runSingleTest` delegates to it.** There
   is exactly one place in the codebase where a proposed spec source becomes a running test,
   and the integrity gate is unconditionally the first thing that happens there. There is no
   parameter, option, environment variable, or code path that disables the gate. Phase 3
   registers only `runSingleTest` with OpenAI.

5. **Substitution is a single exact string-literal replacement, and nothing else.** The tool
   locates the original selector as a *quoted literal* (`'sel'`, `"sel"`, or `` `sel` ``),
   requires exactly one occurrence across all three forms, and replaces it. It does not
   parse TypeScript, does not use an AST, does not add a dependency, and does not rewrite
   anything else. `tests/README.md` already guarantees the precondition: "Every drift-target
   selector is a single string literal occurring exactly once in its file."

6. **The candidate selector is validated for injection before it is ever placed into
   source.** A candidate containing a newline, carriage return, backslash, backtick, `${`,
   both quote characters, or exceeding `MAX_CANDIDATE_SELECTOR_LENGTH` is rejected. This is
   what makes "substitute only the selector" true rather than aspirational — without it a
   candidate like `#x'); test.skip(); ('` is arbitrary code execution inside the spec.

7. **A candidate identical to the original selector is rejected.** Otherwise the agent could
   "verify a fix" that changes nothing, which would report a heal for a test that was never
   repaired. Rejection code: `candidate-identical-to-original`.

8. **The integrity gate is rule-based on the raw source, with no comment stripping and no
   parser.** Hand-rolling a comment stripper introduces bugs (`'http://x'` contains `//`)
   for no benefit: commenting out an assertion is caught by the *comment-marker count* rule
   instead, and deleting one is caught by the expect-count and line-count rules. Every rule
   is a comparison between the two sources, so occurrences inside strings and comments
   affect both sides identically. The gate's design bias is toward **false rejection**, and
   that is the correct bias here.

9. **The original file is hashed before and after every call.** If the post-call SHA-256
   differs from the pre-call SHA-256 the result is forced to `passed: false` with
   `rejected: 'original-spec-mutated'`. This is a self-check for TASKS.md's first acceptance
   criterion ("Original spec file is byte-identical after the call, always"), enforced in
   code and not only in a test.

10. **Bounded, no retries.** One child process, one attempt, killed at
    `RUN_SINGLE_TEST_TIMEOUT_MS`. `playwright.verify.config.ts` sets `retries: 0` and
    `workers: 1`. There is no `while`, no recursion, and no retry-on-failure anywhere in
    this task. `forbidOnly: true` in that config is a second, independent line of defence
    against `.only`.

11. **The pure modules import nothing.** `agent/tools/spec-edit.ts` and
    `agent/tools/assertion-integrity.ts` have **zero** imports — no `node:fs`, no
    `@playwright/test`, nothing. Only `agent/tools/run-single-test.ts` and the CLI touch the
    filesystem or spawn processes. This makes "the gate cannot be influenced by the
    environment" checkable with `grep`.

12. **Tool tests go in the existing `agent/tools/__tests__/` directory under the existing
    `playwright.tools.config.ts`, which stays byte-identical.** The five slow tests raise
    their own limit with `test.setTimeout(...)` rather than loosening the shared config.
    `tests/` stays frozen at 5 specs and `npm run test:e2e` must still report exactly
    5 passed.

13. **No breakage toggling inside a test.** Same precedent as 2.1 and 2.2: a test that shells
    out to `npm run break:on` leaves the repository broken if it crashes. Execution is proven
    against the **pristine** app using an equivalent-selector case (passes) and a
    wrong-element case (fails). Breakage-on behaviour is verified by the Builder's shell
    commands in step 9.

14. **The CLI contract form is direct `npx tsx` invocation**; `npm run --silent
    tool:run-single-test` is the documented convenience wrapper. Identical to 2.1
    decision 10 and 2.2 decision 9. No `.npmrc`, no `loglevel`, no banner-stripping.

15. **No OpenAI tool-schema wrapper in this task.** Same as 2.1 decision 7 and 2.2
    decision 7.

16. **The root `mend-tmp/` directory is durable; only the per-call subdirectory is
    transient.** *(Added in the round-3 revision — see "Revision after round-3 review"
    above.)* `mend-tmp/` is created on demand with `mkdir(..., { recursive: true })` and is
    **never** removed — not in the `finally`, not by a process-exit hook, not by a startup
    sweep. Each call creates and destroys exactly one `mend-tmp/run-XXXXXX/` subdirectory
    beneath it. An **empty `mend-tmp/` left in the working tree is the expected steady
    state**, exactly like `test-results/`, `playwright-report/` and `blob-report/`, all of
    which are gitignored alongside it. Because git does not track directories, an empty
    `mend-tmp/` can never appear in `git status --porcelain`. Do **not** add an `rmdir` of
    the root: swallowing `ENOTEMPTY` does not make it race-free, because a concurrent caller
    sitting between its `mkdir` and its `mkdtemp` sees an empty root that is legitimately
    removable, and its `mkdtemp` then fails with `ENOENT`. The only fix for that race is a
    retry, which decision 10 forbids in the verification path. The correct cleanliness
    assertion everywhere in this plan is therefore **"`mend-tmp/` is absent or empty, and
    contains no `run-*` subdirectory"**, never "`mend-tmp/` does not exist".

### 2. `agent/tools/spec-edit.ts`

TypeScript, strict, **zero imports**. This file must contain no `import` statement at all.

Exported constants:

```ts
export const MAX_CANDIDATE_SELECTOR_LENGTH = 200;
export const FORBIDDEN_SELECTOR_SUBSTRINGS: readonly string[] = ['\n', '\r', '\\', '`', '${'];
```

Exported helper (used by the integrity gate as well, so it lives here and is imported there
— that is the **one** permitted exception to the zero-import rule, and it applies to
`assertion-integrity.ts` importing from `./spec-edit.js`, not to this file importing
anything):

```ts
export function extractStringLiterals(source: string): readonly string[];
```

Implementation: apply the following regex globally and return every match **including its
delimiters**, in source order.

```ts
const STRING_LITERAL_PATTERN =
  /'(?:[^'\\\n]|\\.)*'|"(?:[^"\\\n]|\\.)*"|`(?:[^`\\]|\\.)*`/g;
```

Declare this pattern as a module-level `const` and create a fresh `RegExp` per call (or reset
`lastIndex`) so repeated calls are not order-dependent. Recommended: build it inside the
function body to sidestep the `lastIndex` hazard entirely.

Main function:

```ts
export function applySelectorSubstitution(
  originalSource: string,
  originalSelector: string,
  candidateSelector: string,
): SubstitutionResult
```

Behaviour, in this exact order. There is no loop other than the bounded occurrence scan and
no retry.

1. **Candidate safety.** In this order, returning immediately on the first failure with
   `ok: false`, `proposedSource: null`, `fromLiteral: null`, `toLiteral: null`,
   `occurrences: 0`, and a human-readable `detail`:
   - `candidateSelector.trim().length === 0` → `failure: 'unsafe-candidate-selector'`,
     detail `candidate selector must be a non-empty string`.
   - `candidateSelector.length > MAX_CANDIDATE_SELECTOR_LENGTH` →
     `failure: 'unsafe-candidate-selector'`, detail
     `candidate selector exceeds ${MAX_CANDIDATE_SELECTOR_LENGTH} characters`.
   - `candidateSelector` contains any entry of `FORBIDDEN_SELECTOR_SUBSTRINGS` →
     `failure: 'unsafe-candidate-selector'`, detail
     `candidate selector contains a forbidden substring: <the entry, JSON.stringify'd>`.
   - `candidateSelector === originalSelector` →
     `failure: 'candidate-identical-to-original'`, detail
     `candidate selector is identical to the original selector`.
2. **Quote choice.** `quote = !candidateSelector.includes("'") ? "'"
   : !candidateSelector.includes('"') ? '"' : null`. If `null` →
   `failure: 'unsafe-candidate-selector'`, detail
   `candidate selector contains both quote characters`.
3. **Locate the original literal.** For each `q` of `["'", '"', '`']` build
   `q + originalSelector + q` and count **non-overlapping** occurrences in `originalSource`
   with an `indexOf` scan. Let `occurrences` be the sum over all three forms.
   - `occurrences === 0` → `failure: 'selector-not-found'`, detail
     `original selector literal not found in spec source`.
   - `occurrences > 1` → `failure: 'selector-ambiguous'`, detail
     `original selector literal occurs ${occurrences} times; exactly one is required`.
4. **Substitute.** `fromLiteral` is the single form that occurred;
   `toLiteral = quote + candidateSelector + quote`. Produce `proposedSource` by replacing
   that one occurrence — use `source.slice(0, idx) + toLiteral + source.slice(idx +
   fromLiteral.length)`. Do **not** use `String.prototype.replace` with a string pattern
   containing `$` sequences, and do **not** use a regex.
5. Return `{ ok: true, proposedSource, fromLiteral, toLiteral, occurrences: 1,
   failure: null, detail: '' }`.

### 3. `agent/tools/assertion-integrity.ts`

TypeScript, strict. Its **only** import is
`import { extractStringLiterals } from './spec-edit.js';`. No `node:*`, no
`@playwright/test`, no filesystem, no environment reads.

Exported constants:

```ts
export const ASSERTION_MATCHERS: readonly string[] = [
  'toBeVisible', 'toBeHidden', 'toBeAttached', 'toBeFocused', 'toBeEditable',
  'toBeEnabled', 'toBeDisabled', 'toBeChecked', 'toBeEmpty',
  'toHaveText', 'toContainText', 'toHaveValue', 'toHaveValues', 'toHaveCount',
  'toHaveAttribute', 'toHaveClass', 'toHaveId', 'toHaveCSS', 'toHaveJSProperty',
  'toHaveURL', 'toHaveTitle', 'toHaveScreenshot', 'toMatchAriaSnapshot',
  'toBe', 'toEqual', 'toStrictEqual', 'toContain', 'toMatch', 'toMatchObject',
  'toThrow', 'toThrowError', 'toBeTruthy', 'toBeFalsy', 'toBeNull', 'toBeUndefined',
  'toBeDefined', 'toBeNaN', 'toBeCloseTo', 'toBeGreaterThan', 'toBeGreaterThanOrEqual',
  'toBeLessThan', 'toBeLessThanOrEqual', 'toBeInstanceOf', 'toHaveLength',
  'toHaveProperty',
];
```

Main function:

```ts
export function checkAssertionIntegrity(
  originalSource: string,
  proposedSource: string,
  allowedLiteralChange: AllowedLiteralChange | null,
): AssertionIntegrityResult
```

It evaluates the eight rules below **in this exact order**, accumulating **every** violation
(it does not stop at the first). `ok` is `violations.length === 0`.

Use a private helper `countMatches(source: string, pattern: RegExp): number` that constructs
a fresh global RegExp per call.

| # | `rule` id | Pattern / measure | Violation condition | `detail` format |
| --- | --- | --- | --- | --- |
| 1 | `expect-count` | `/\bexpect\s*\(/g` | proposed **<** original | `expect( occurrences <o> -> <p>` |
| 2 | `matcher-inventory` | for each `m` in `ASSERTION_MATCHERS`: `new RegExp('\\.' + m + '\\s*\\(', 'g')` | proposed **≠** original, one violation per differing matcher, in `ASSERTION_MATCHERS` order | `.<m>( occurrences <o> -> <p>` |
| 3 | `negation-count` | `/\.not\b/g` | proposed **≠** original | `.not occurrences <o> -> <p>` |
| 4 | `await-count` | `/\bawait\b/g` | proposed **≠** original | `await occurrences <o> -> <p>` |
| 5 | `skip-only` | `/\.\s*(?:skip\|only\|fixme\|fail\|soft)\b/g` | proposed **>** original | `.skip/.only/.fixme/.fail/.soft occurrences <o> -> <p>` |
| 6 | `comment-count` | `/\/\/\|\/\*/g` | proposed **>** original | `comment markers <o> -> <p>` |
| 7 | `line-count` | `source.split('\n').length` | proposed **≠** original | `line count <o> -> <p>` |
| 8 | `string-literals` | `extractStringLiterals` multiset difference | see below | `unexpected string literal changes: removed [<...>] added [<...>]` |

Rule 8 in full. Build count maps of the literal arrays. `removed` is every literal whose
original count exceeds its proposed count, repeated by the delta, in first-appearance order
in the original. `added` is the mirror image, in first-appearance order in the proposed.
The rule is satisfied if and only if:

* `removed.length === 0 && added.length === 0`, **or**
* `allowedLiteralChange !== null && removed.length === 1 && added.length === 1 &&
  removed[0] === allowedLiteralChange.fromLiteral &&
  added[0] === allowedLiteralChange.toLiteral`.

Anything else is a violation. In particular, when `allowedLiteralChange` is `null` the
literal multiset must be **exactly** identical. This is the rule that stops a candidate
weakening an expected value (`toHaveText('Signed in as user@example.com')` →
`toHaveText('')`) while pretending to be a selector change.

Also export the deterministic line-change summary used by `run-single-test.ts`:

```ts
export function diffChangedLines(
  originalSource: string,
  proposedSource: string,
): readonly SpecLineChange[];
```

Split both on `'\n'`. If the lengths differ, return `[]`. Otherwise return one
`{ lineNumber, before, after }` entry (1-based) for every index where the lines differ, in
index order.

### 4. `playwright.verify.config.ts`

suite and never runs the tool tests.

```ts

export default defineConfig({
  testDir: process.env['MEND_VERIFY_DIR'] ?? './mend-tmp',
  outputDir: './test-results/verify-artifacts',
  fullyParallel: false,
  workers: 1,
  retries: 0,
  forbidOnly: true,
  timeout: 15_000,

  reporter: [

    ['json', { outputFile: process.env['MEND_VERIFY_JSON'] ?? 'test-results/verify.json' }],

```

`timeout`, `expect.timeout`, `actionTimeout` and `navigationTimeout` deliberately mirror
`playwright.config.ts` exactly, so a verification re-run behaves identically to the baseline
suite. Do not "speed up" verification by shortening them — the seeded failure signatures in
`tests/README.md` depend on the 5000 ms action timeout. `retries: 0` is non-negotiable: a
retry would let a flaky pass be recorded as a heal.

#### `verifySpecSource`

```ts
export async function verifySpecSource(input: VerifySpecSourceInput): Promise<RunSingleTestResult>
```

Order of operations, exactly:

1. `const startedAt = Date.now();`
2. `const specPath = resolve(REPO_ROOT, input.specFile);`
3. Read the original: `originalSource = await readFile(specPath, 'utf8')` inside a `try`. On
   throw return `rejectedResult('spec-file-unreadable', message)`.
   `const originalHash = sha256(originalSource);`
4. **Integrity gate — before anything is written or spawned.**
   `const integrity = checkAssertionIntegrity(originalSource, input.proposedSource,
   input.allowedLiteralChange);`
   If `!integrity.ok`, return immediately with `passed: false`, `executed: false`,
   `rejected: 'assertion-integrity'`, `violations: integrity.violations`,
   `output: ''`, `exitCode: null`, `timedOut: false`.
5. Create the temp directory, in two steps. First the **durable root** (decision 16):
   ```ts
   const tempRootDir = join(REPO_ROOT, TEMP_ROOT_DIR_NAME);
   await mkdir(tempRootDir, { recursive: true });
   ```
   This root is created on demand and is **never removed** — not here, not in the `finally`,
   not anywhere else in the codebase. An empty `mend-tmp/` surviving in the working tree is
   the expected steady state.
   Then the **transient per-call subdirectory**:
   ```ts
   const tempDir = await mkdtemp(tempRootDir + '/run-');
   ```
   (`mkdtemp` takes a *prefix*, not a directory.)
   Write `join(tempDir, basename(specPath))` with `input.proposedSource`.
   Everything from here to the end is inside a
   `try { } finally { await rm(tempDir, { recursive: true, force: true }); }`.
   The `finally` removes **only** `tempDir`. It must not touch `tempRootDir`, must not call
   `rmdir`, and must not be paired with a process-exit hook or a startup sweep — see
   decision 16 for why every such variant races a concurrent caller.
6. Spawn the child:
   ```
   spawn(process.execPath,
         [PLAYWRIGHT_CLI, 'test', `--config=${VERIFY_CONFIG_PATH}`,
          `--grep=${escapeRegExp(input.testName)}`],
         { cwd: REPO_ROOT, env: { ...childEnv(), MEND_VERIFY_DIR: tempDir,
                                  MEND_VERIFY_JSON: join(tempDir, 'results.json') } })
   ```
   Do **not** pass `--reporter`; the config owns the reporters. Do **not** pass a positional
   file filter; `MEND_VERIFY_DIR` already scopes collection to the one temp directory.
   Concatenate `stdout` and `stderr` into a single buffer in arrival order. Set one
   `setTimeout(..., input.timeoutMs ?? RUN_SINGLE_TEST_TIMEOUT_MS)` that calls
   `child.kill('SIGKILL')` and records `timedOut = true`; clear it on `close`. Resolve on the
   `close` event with `{ exitCode, timedOut, output }`. On the `error` event (spawn failure)
   resolve with `exitCode: null` and the error message appended to `output`.
7. Read and parse `join(tempDir, 'results.json')`. On any read/parse failure set
   `rejected = 'results-unavailable'`, `passed = false`. Otherwise take
   `report.stats as { expected: number; unexpected: number; flaky: number; skipped: number }`
   defensively (treat a missing field as `NaN`, which fails every comparison below) and set:
   ```
   passed = exitCode === 0 && !timedOut
            && stats.expected === 1 && stats.unexpected === 0
            && stats.flaky === 0 && stats.skipped === 0;
   ```
8. **Post-run hash check.** Re-read `specPath` and recompute the hash. If it differs from
   `originalHash`, force `passed = false` and `rejected = 'original-spec-mutated'`.
9. Return the full `RunSingleTestResult` with `executed: true`,
   `output: clampOutput(output)`, `violations: []`,
   `changedLines: diffChangedLines(originalSource, input.proposedSource)`,
   `durationMs: Date.now() - startedAt`.

There is exactly **one** `spawn` call in this file and exactly **one** place where a
`playwright test` command is constructed.

#### `runSingleTest`

```ts
export async function runSingleTest(input: RunSingleTestInput): Promise<RunSingleTestResult>
```

1. Read the original spec (same `resolve` + `readFile` + `spec-file-unreadable` handling).
2. `const sub = applySelectorSubstitution(originalSource, input.originalSelector,
   input.candidateSelector);`
3. If `!sub.ok`, return `passed: false`, `executed: false`,
   `rejected: sub.failure` (which is already one of `unsafe-candidate-selector`,
   `candidate-identical-to-original`, `selector-not-found`, `selector-ambiguous`),
   `output: sub.detail`, `violations: []`, `proposedSource: null`, `changedLines: []`,
   `exitCode: null`, `timedOut: false`.
4. Otherwise delegate:
   ```ts
   return verifySpecSource({
     specFile: input.specFile,
     testName: input.testName,
     proposedSource: sub.proposedSource,
     allowedLiteralChange: { fromLiteral: sub.fromLiteral, toLiteral: sub.toLiteral },
     timeoutMs: input.timeoutMs,
   });
   ```
   and then set `originalSelector` / `candidateSelector` on the returned object from the
   input (build the returned object explicitly rather than mutating — every field of
   `RunSingleTestResult` is `readonly`).

`runSingleTest` reads the spec twice (once here, once inside `verifySpecSource`). That is
accepted: it keeps `verifySpecSource` self-contained and the gate un-bypassable.

### 6. `agent/tools/cli/run-single-test.cli.ts`

Zero interactivity, no argument-parsing library. Modelled on
`agent/tools/cli/query-selector.cli.ts`.

```
Usage: npx tsx agent/tools/cli/run-single-test.cli.ts --spec=<path> --test=<title> --original=<selector> --candidate=<selector> [--json]
   or: npm run --silent tool:run-single-test -- --spec=<path> --test=<title> --original=<selector> --candidate=<selector> [--json]
```

Parsing: `const args = process.argv.slice(2);`, `const json = args.includes('--json');`, and
a small `readFlag(name: string): string | undefined` that finds the first arg starting with
`--${name}=` and returns the remainder. All four of `spec`, `test`, `original`, `candidate`
are required; if any is `undefined` or empty, print the two usage lines to **stderr** and
`process.exit(2)` with nothing on stdout. Narrow with explicit `=== undefined` checks, never
with `!`.

Output:

- With `--json`: `console.log(JSON.stringify(result, null, 2));` — and nothing else on
  stdout. Note this includes `proposedSource`.
- Without `--json`, stdout gets exactly this, in this order:
  ```
  spec=<specFile> test=<testName> original=<originalSelector> candidate=<candidateSelector>
  passed=<passed> executed=<executed> rejected=<rejected ?? 'none'> exitCode=<exitCode ?? '-'> timedOut=<timedOut> durationMs=<durationMs>
  ```
  followed by one line per integrity violation, `violation: <rule> <detail>`, followed by
  the literal line `--- test output ---` and then `result.output` (omit both if `output` is
  empty).
- Exit code (Q2): `0` if `result.passed === true`; `3` if a result was produced but
  `passed === false`; `2` for a usage error; `1` if `runSingleTest` itself threw (print
  `run_single_test failed: <message>` to stderr first).

The CLI contains no logic that inspects, filters, or strips its own output stream.

## Risks

- **Nested Playwright: the child run misbehaves because it inherits the parent runner's
  environment.** This is the single most likely blocker, and it only appears in tests 18, 19
  and 22. Symptoms: "Playwright Test did not expect test() to be called here", the child
  writing into the parent's output directory, or the child silently finding zero tests. The
  mitigation is specified — `childEnv()` strips every `PW_*`, `PWTEST_*` and `PLAYWRIGHT_*`
  key except `PLAYWRIGHT_BROWSERS_PATH`, plus `TEST_WORKER_INDEX`, `TEST_PARALLEL_INDEX` and
  `FORCE_COLOR`. If it still fails, report **Blocked / unclear** with the exact child stderr.
  Do **not** "fix" it by moving the execution tests out of the Playwright runner, by mocking
  the spawn, or by asserting on anything other than a real child process.

- **`MEND_VERIFY_DIR` is read at config-load time and Playwright caches the config.** The
  child is a fresh process per call, so this is safe by construction. If the Builder is
  tempted to reuse a single long-lived child or a config-level cache, don't — one call, one
  process.

- **Playwright's JSON report `stats` shape differs from the plan's assumption.** The expected
  shape is `{ startTime, duration, expected, unexpected, flaky, skipped }`. Read it
  defensively (a missing field becomes `NaN` and therefore fails the equality checks, so the
  fail-safe direction is `passed: false`). If the field names differ in the installed
  Playwright version, report the actual JSON shape and **Blocked / unclear** — do not fall
  back to grepping stdout for `"1 passed"`, which decision 2 forbids.

- **`createRequire(import.meta.url).resolve('playwright/cli.js')` throws.** `playwright` is a
  transitive dependency of `@playwright/test` and `node_modules/playwright/cli.js` exists in
  this repo. If resolution fails, try `'playwright/cli'` (no extension) and report which
  worked. If neither resolves, report **Blocked / unclear** — do not fall back to spawning
  `npx`, which introduces network and shell-resolution failure modes into the verification
  gate.

- **`--grep` matches zero tests or more than one.** Playwright greps against the composed
  `project > file > title` string, so the pattern must not be anchored with `^`/`$`. If the
  title contains regex metacharacters, `escapeRegExp` handles them. If a run reports
  `stats.expected === 0`, the result is correctly `passed: false`; investigate the grep
  string rather than relaxing the `stats.expected === 1` condition. **Never** weaken that
  condition — it is what stops "zero tests ran" from being read as success.

- **The integrity gate is too strict and rejects a legitimate substitution.** The
  `line-count`, `await-count`, `negation-count` and `matcher-inventory` rules all require
  *equality*, which is correct for this tool because substitution never changes any of them.
  If test 8 (the accepting case) fails, the bug is in the substitution or in the rule
  implementation — do **not** relax a rule from equality to inequality to make a test pass.
  Report **Blocked / unclear** if a rule genuinely blocks a legitimate substitution.

- **`extractStringLiterals` mis-tokenises.** A regex-based literal scanner is approximate: a
  quote inside a line comment, or an apostrophe in prose, can shift the match boundaries.
  Because every rule compares the *same* function's output on both sources, a mis-tokenisation
  produces symmetric noise and biases toward false rejection, not false acceptance. If test 8
  fails because of tokenisation, fix the regex; do not delete the `string-literals` rule — it
  is the only rule that catches test 13.

- **`mkdtemp` on a path whose parent does not exist.** `mkdtemp(join(root, 'mend-tmp') +
  '/run-')` fails unless `mend-tmp/` exists. Create it with `mkdir(..., { recursive: true })`
  first, as specified. Note that `mkdtemp` takes a *prefix*, not a directory. The root is
  created on demand and then deliberately left in place forever (decision 16), which is
  exactly what keeps this `mkdir`/`mkdtemp` pair free of a TOCTOU race.

- **The temp directory survives a crash.** The `finally` covers thrown errors, but not
  `SIGKILL` of the parent. `mend-tmp/` is gitignored and outside every `testDir`, so a
  survivor cannot pollute `npm run test:e2e` or `npm run test:tools`. Do not add a
  process-exit hook or a startup sweep of `mend-tmp/` — a sweep would race concurrent calls,
  which Phase 3 may make. The same reasoning is why the **root** `mend-tmp/` directory is
  never removed either, not even with a "safe" `rmdir` that swallows `ENOTEMPTY`: see
  decision 16 and the round-3 revision note at the top of this plan. A stale
  `mend-tmp/run-XXXXXX/` left by a `SIGKILL`ed parent is acceptable and is not a review
  failure; an empty root `mend-tmp/` is expected, not a leak.

- **Test 18's candidate is not actually equivalent.** `#login-form #login-btn` assumes the
  button sits inside an element with `id="login-form"`. Verify this against
  `app-under-test/index.html` before writing the test. If it does not hold, pick another
  genuinely equivalent selector that resolves to the same single element (e.g.
  `button#login-btn`) and say so in the Deviations section — this is the one place the
  Builder may substitute a value, and only after confirming with `query_selector` that the
  chosen selector has `matchCount === 1` and `previews[0].id === 'login-btn'`.

- **Tests 18, 19 and 22 are slow.** Each spawns a browser through a child Playwright run;
  budget 15–40 s each. `test.setTimeout(180_000)` is specified for exactly this reason. If
  the whole tools suite becomes unpleasantly slow, that is accepted for this task — do not
  reduce the number of execution tests, and do not lower
  `playwright.verify.config.ts`'s timeouts to speed them up.

- **`noUncheckedIndexedAccess` friction.** `removed[0]`, `added[0]`, `lines[i]` and
  `process.env['X']` are all `T | undefined`. Narrow with explicit `=== undefined` guards.
