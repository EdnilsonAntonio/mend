# Plan: 8.1 — Fail loudly on unreachable database in `db:migrate`

## Goal

After this task, `npm run db:migrate` (and `npm run db:migrate:status`) can never exit
non-zero without printing a specific, actionable explanation. A connection failure is
classified into one of five named kinds — `server-unreachable`, `host-not-found`,
`database-missing`, `authentication-failed`, `unknown` — and rendered as a headline, a
password-free description of the connection target, the underlying cause, and a one-line
hint. On success the command's last line is an explicit `Applied N migrations …` summary.
A spawn-based test asserts on the *printed text* for an unreachable `DATABASE_URL`, so the
silent-failure defect cannot regress.

### Root cause (the Builder must fix this, not just paper over it)

`db/cli/migrate.cli.ts` already has a `catch` that does
`console.error(err instanceof Error ? err.message : String(err))`. It produces no visible
output because of two compounding defects:

1. **Empty-message errors.** When `DATABASE_URL` points at a hostname that resolves to
   multiple addresses (e.g. `localhost` → `::1` and `127.0.0.1`) and nothing is listening,
   Node rejects with an `AggregateError` whose `.message` is the **empty string** and whose
   real `ECONNREFUSED` errors live in `.errors[]`. `console.error('')` prints a blank line.
   The current code has no path that guarantees a non-empty message.
2. **Error masking in `finally`.** `db/migrate.ts` closes with `finally { await client.end(); }`
   (lines 191–194 and 249–251) and `finally { await client.query('SELECT pg_advisory_unlock…') }`
   (line 187–190). If the connection is dead, those awaited calls can reject and replace the
   real diagnosis with a second, less useful error — or leave nothing useful at all.

Both are addressed below. The Builder must not "fix" this by only editing the CLI's catch
block.

### Step 2 — `db/connection-errors.ts`: create the classifier (new file)

Imports: `import { MigrationError } from './migration-files.js';` — and nothing else. This
module must not import `pg` or perform I/O.

Implement, in this order, exactly the exported names and signatures given in
**Interfaces / types** below:

1. `UNREACHABLE_HEADLINE` — the pinned literal string.
2. `CONNECTION_FAILURE_HINTS` — `Record<ConnectionFailureKind, string>`.
3. `parseConnectionTarget(connectionString)` — `new URL(connectionString)` inside
   `try`/`catch`. On success:
   - `host` = `url.hostname` or `'(unset)'` if empty
   - `port` = `url.port` or `'5432'` if empty
   - `database` = `decodeURIComponent(url.pathname.replace(/^\//, ''))` or `'(unset)'` if empty
   - `user` = `decodeURIComponent(url.username)` or `'(unset)'` if empty
   - `parsed: true`

   On `catch`: return `{ host: '(unparsed)', port: '(unparsed)', database: '(unparsed)',
   user: '(unparsed)', parsed: false }`. **Never** read `url.password` anywhere in this file.
4. `describeConnectionTarget(target)` — returns
   `host=<host> port=<port> database=<database> user=<user>` when `target.parsed` is true, and
   `DATABASE_URL could not be parsed as a postgres:// URL` when it is false.
5. `collectErrorCodes(error)` — returns `readonly string[]`. Walk `error` breadth-first,
   following `(error as { errors?: unknown }).errors` when it is an array and
   `(error as { cause?: unknown }).cause` when it is a non-null object. Maximum depth 5,
   maximum 32 visited nodes (guards against cyclic `cause` chains). At each node, if
   `typeof node.code === 'string'` and non-empty, push it. Return the collected codes in
   visit order; duplicates are allowed.
6. `describeError(error)` — returns a **guaranteed non-empty** string. In order:
   - if `error` is an object with a string `message` whose `.trim()` is non-empty → return that message;
   - else if `Array.isArray((error as { errors?: unknown }).errors)` → recurse into each child
     with `describeError`, drop duplicates, join with `'; '`, return it if non-empty;
   - else if `typeof (error as { code?: unknown }).code === 'string'` and non-empty → return the code;
   - else compute `String(error)`; return it if non-empty and not `'[object Object]'`;
   - else return `(error as { constructor?: { name?: string } })?.constructor?.name ?? 'unknown error'`,
     falling back to `'unknown error'` if that is empty.

   Recursion depth is bounded at 3 via a private second parameter that is **not** part of the
   exported signature (use a module-private helper if the extra parameter would change the
   public shape).
7. `classifyConnectionError(error, connectionString)` — returns `ConnectionDiagnosis`.
   - `const target = parseConnectionTarget(connectionString);`
   - `const codes = collectErrorCodes(error);`
   - `const cause = describeError(error);`
   - Determine `kind` by the **first** matching rule, in exactly this order:
     1. `codes` includes `'3D000'` → `'database-missing'`
     2. `codes` includes any of `'28P01'`, `'28000'`, `'28P02'` → `'authentication-failed'`
     3. `codes` includes any of `'ENOTFOUND'`, `'EAI_AGAIN'` → `'host-not-found'`
     4. `codes` includes any of `'ECONNREFUSED'`, `'ECONNRESET'`, `'EHOSTUNREACH'`,
        `'ENETUNREACH'`, `'ETIMEDOUT'`, `'EPIPE'`, `'ERR_SOCKET_CONNECTION_TIMEOUT'` →
        `'server-unreachable'`
     5. `/database .* does not exist/i.test(cause)` → `'database-missing'`
     6. `/password authentication failed|no pg_hba\.conf entry/i.test(cause)` → `'authentication-failed'`
     7. `/(connect|connection).*(timeout|timed out)|timeout.*connect/i.test(cause)` → `'server-unreachable'`
     8. otherwise → `'unknown'`
   - `headline` by kind:
     - `'server-unreachable'` → `UNREACHABLE_HEADLINE` (exact literal, no interpolation)
     - `'database-missing'` → `` `Reached the Postgres server, but database "${target.database}" does not exist.` ``
     - `'host-not-found'` → `` `Could not resolve the database host "${target.host}" from DATABASE_URL.` ``
     - `'authentication-failed'` → `` `Reached the Postgres server, but authentication failed for user "${target.user}".` ``
     - `'unknown'` → `'Could not connect to the database in DATABASE_URL.'`
   - `hint` = `CONNECTION_FAILURE_HINTS[kind]`
   - Return `{ kind, headline, cause, hint, target }`.
8. `formatConnectionFailure(diagnosis)` — returns a multi-line string, lines joined with `'\n'`:
   ```
   <headline>
     target: <describeConnectionTarget(diagnosis.target)>
     cause:  <diagnosis.cause>
   <hint>
   ```
   (Two spaces of indent on the `target:`/`cause:` lines; `cause:` has two spaces after the
   colon so the values align.) If `diagnosis.cause` contains newlines, collapse them: replace
   `/\s*\n\s*/g` with `' '` before interpolating.
9. `DatabaseConnectionError extends MigrationError` — constructor
   `(diagnosis: ConnectionDiagnosis, options?: { cause?: unknown })`, calls
   `super('connection-failed', formatConnectionFailure(diagnosis), options)`, sets
   `this.name = 'DatabaseConnectionError'` and `this.diagnosis = diagnosis`.

### Step 3 — `db/client.ts`: add connect/close helpers

Add at the end of the file:

```ts
export async function connectDbClient(
  client: PgClient,
  connectionString: string,
): Promise<void> {
  try {
    await client.connect();
  } catch (error) {
    throw new DatabaseConnectionError(
      classifyConnectionError(error, connectionString),
      { cause: error },
    );
  }
}

export async function closeDbClientQuietly(client: PgClient): Promise<void> {
  try {
    await client.end();
  } catch {
    // Closing a client whose connection already failed must never mask the
    // original diagnosis. Swallowing here is deliberate.
  }
}
```

Add the import: `import { classifyConnectionError, DatabaseConnectionError } from './connection-errors.js';`

There is no import cycle: `connection-errors.ts` → `migration-files.ts` only.

## Interfaces / types

Copy-paste ready. `db/connection-errors.ts`:

```ts
import { MigrationError } from './migration-files.js';

export type ConnectionFailureKind =
  | 'server-unreachable'
  | 'host-not-found'
  | 'database-missing'
  | 'authentication-failed'
  | 'unknown';

/** Pinned by spec/TASKS.md Task 8.1. Do not reword. */
export const UNREACHABLE_HEADLINE =
  'Could not reach DATABASE_URL — is Postgres running and is the database created?';

export const CONNECTION_FAILURE_HINTS: Record<ConnectionFailureKind, string> = {
  'server-unreachable':
    'Hint: start Postgres and check the host and port in DATABASE_URL. db/README.md has a ready-to-run Docker command.',
  'host-not-found':
    'Hint: check the hostname in DATABASE_URL for a typo, and that it resolves from this machine.',
  'database-missing':
    "Hint: create it with `createdb <name>` (or `psql -c 'CREATE DATABASE <name>'`), then re-run `npm run db:migrate`.",
  'authentication-failed':
    'Hint: check the user and password in DATABASE_URL against the server’s credentials.',
  unknown:
    'Hint: check DATABASE_URL, then see db/README.md for the expected connection-string format.',
};

/** Host/port/database/user parsed from a connection string. Never holds the password. */
export interface ConnectionTarget {
  readonly host: string;
  readonly port: string;
  readonly database: string;
  readonly user: string;
  /** False when the connection string is not a parsable URL. */
  readonly parsed: boolean;
}

export interface ConnectionDiagnosis {
  readonly kind: ConnectionFailureKind;
  /** First printed line. Specific to the kind. */
  readonly headline: string;
  /** Non-empty description of the underlying error. Never the empty string. */
  readonly cause: string;
  /** One-line actionable next step. */
  readonly hint: string;
  readonly target: ConnectionTarget;
}

export function parseConnectionTarget(connectionString: string): ConnectionTarget;

/** e.g. `host=127.0.0.1 port=1 database=mend_nope user=mend_user`. Never includes a password. */
export function describeConnectionTarget(target: ConnectionTarget): string;

/** All string `code` values found on the error, its `errors[]`, and its `cause` chain. */
export function collectErrorCodes(error: unknown): readonly string[];

/** Always returns a non-empty string, for any input including `undefined` and `AggregateError`. */
export function describeError(error: unknown): string;

export function classifyConnectionError(
  error: unknown,
  connectionString: string,
): ConnectionDiagnosis;

/** Four lines: headline, indented target, indented cause, hint. */
export function formatConnectionFailure(diagnosis: ConnectionDiagnosis): string;

export class DatabaseConnectionError extends MigrationError {
  readonly diagnosis: ConnectionDiagnosis;
  constructor(diagnosis: ConnectionDiagnosis, options?: { cause?: unknown });
}
```

## Risks

- **The process no longer exits promptly.** Replacing `process.exit()` with
  `process.exitCode` means Node exits only when the event loop drains. Both `db/migrate.ts`
  code paths now always run `closeDbClientQuietly`, so no pg socket should remain. If
  `npm run db:migrate` visibly hangs after printing its output, **stop and report it as
  Blocked** rather than reintroducing `process.exit()` — the hang is a real open-handle leak
  that needs a design answer, not a workaround.
- **Port 1 behaves differently on some hosts.** The CLI test assumes `127.0.0.1:1` refuses
  immediately. If it instead hangs, the 20 s guard in `runMigrateCli` fires and the test
  fails loudly. If that happens, report it — do not silently switch to `test.skip`.
- **`localhost` may resolve to a single address in the Builder's environment**, so the
  `REFUSED_HOST_URL` case may not produce an `AggregateError`. That is fine: the assertion is
  on the printed headline, which holds either way. The unit test in Step 6 case (2) covers
  the `AggregateError` shape deterministically regardless of DNS.
- **`noUnusedLocals`/`noUnusedParameters` are on.** Removing the `MigrationError` import from
  `db/cli/migrate.cli.ts` is mandatory once the ternary is gone, or `npm run typecheck` fails.
- **`noUncheckedIndexedAccess` is on.** Any array indexing in the new code (e.g. splitting
  formatted output into lines in tests) must handle `T | undefined`.
- **Swallowing close/unlock errors could hide a genuine problem.** This is a deliberate
  trade: the original error is strictly more useful than a secondary teardown error. Do not
  extend this swallowing to anything other than `client.end()` and `pg_advisory_unlock`.
- **Message drift.** `UNREACHABLE_HEADLINE` is asserted verbatim in two test files and quoted
  in `spec/TASKS.md`. Note the em dash (`—`) and that it is a single U+2014 character, not
  a hyphen. Define it once and import it; never retype the literal.
