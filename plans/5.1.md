# Plan: 5.1 — GitHub PR creation

## Goal

After this task, a verified **high-confidence** heal produces a real pull request on GitHub:
a branch is created from the base branch, one commit containing only the patched spec file is
pushed via the GitHub REST API (Octokit), and a PR is opened whose body carries the unified
diff plus a factual summary of what the agent did. The resulting `html_url` is persisted to
`heal_attempts.pr_url`. Nothing else can open a PR: `assertPrEligible` is called before the
first GitHub call, and a second, independent assertion-integrity check is run against the
patch before any commit is created — so a PR can never contain a weakened assertion, and a
`low` or `none` attempt can never reach the GitHub client at all. When GitHub is unreachable
or rejects the request, the attempt is persisted as `needs_review` **with its proposed
selector and full transcript intact**, so the fix is never lost; the tool retries nothing and
merges nothing. The spec file on disk is never modified — the patched source exists only in
memory and in the GitHub commit.

---

## Read this before you start: the five ways to ruin this task

**1. Opening a PR without `assertPrEligible`.** Task 3.4 created `assertPrEligible` for exactly
this task and plan 3.4 records the obligation: *"Task 5.1 must call `assertPrEligible` before it
creates a branch."* It is called in **two** places in this plan — in `runHeal` before the
opener is invoked, and inside the opener itself as the first statement. Both. Do not remove
either as "redundant"; the second one is what makes the delivery module safe in isolation.

**2. Trusting the heal loop's word about the patch.** `HealResult` does **not** store the
patched spec source. This task recomputes it with `applySelectorSubstitution` and then re-runs
`checkAssertionIntegrity` on the result. If either fails, no PR is opened. Do not skip the
second integrity check on the grounds that `run_single_test` already did one.

**3. Writing the patched spec to disk.** `REQUIREMENTS.md`: *"Does not modify test files in
place."* The patched source goes into an Octokit request body and nowhere else. There is no
`writeFile` anywhere in this task. `git status --porcelain tests/` must print nothing after a
run.

**4. Retrying a failed GitHub call.** Each of the six API calls is made **once**. No backoff,
no polling, no "wait for the branch to appear", no second attempt with a different branch name.
A failure is a structured, recorded outcome — that is the whole point of criterion 3.

**5. Modifying `agent/`, `tests/`, `app-under-test/`, `breakage/`, or `db/migrations/`.**
At the end of this task
`git diff HEAD --name-only -- agent/ tests/ app-under-test/ breakage/ db/migrations/`
must print nothing. The `pr_url` column and its
`heal_attempts_pr_url_requires_high_confidence` CHECK already exist from Task 4.1. No
migration is added. If a CHECK rejects a write, the write is wrong, not the constraint.

## Open questions — answer at the approval gate

These are escalations, not decisions taken unilaterally. **If the human does not answer, the
recommendation stands and the Builder proceeds with it.** Everything below this section assumes
every recommendation is accepted.

### Q1 — What does "API failure marks the attempt as needing review" mean at the row level? (the important one)

`TASKS.md` 5.1 says a GitHub API failure must mark the attempt as *needing review* and must
never lose the fix. But `heal_attempts` has a CHECK constraint
(`heal_attempts_status_matches_confidence`, Task 4.1) that forces
`status='needs_review'` ⟺ `confidence='low'`. So writing `needs_review` necessarily overwrites
the `confidence` column that the gate computed as `high`. There is no shape of the current
schema in which a row is `needs_review` and `high` at once.

| Option | Behaviour | Trade-off |
| --- | --- | --- |
| **A (recommended)** | PR delivery is attempted **between** the assessment and the single terminal `settleHealAttempt`. Success → settle `healed`/`high`, then `recordPrUrl`. Failure → settle `needs_review`/`low`, `proposed_selector` **kept**, `failure_reason='pr-delivery-failed: …'`, transcript persisted from the *unmodified* assessment (so `transcript->>'confidence'` is still `'high'` and `transcript->>'prEligible'` is still `true`). | Satisfies the criterion literally, keeps 4.2's "exactly one terminal UPDATE" and its `WHERE status='investigating'` guard, needs no migration, and loses nothing: the selector, the transcript, and the true gate verdict all survive. Cost: the `confidence` **column** can disagree with the gate verdict recorded in the transcript when GitHub is down. Phase 7 must read the gate verdict from `transcript->>'confidence'`, not the column, if it wants a GitHub-independent heal rate. This plan documents that in `db/README.md`. |
| B | Settle `healed`/`high` first, then open the PR, then `UPDATE … SET status='needs_review'` on failure. | Two terminal UPDATEs, and it defeats `settleHealAttempt`'s `WHERE status='investigating'` idempotency guard, which is the mechanism that makes a terminal row unoverwritable. Rejected. |
| C | Keep the row `healed`/`high` with `pr_url IS NULL` and record the delivery error somewhere; "needs review" is expressed as the query `status='healed' AND pr_url IS NULL`. | Keeps `confidence` honest, but the status enum value `needs_review` is never used, so the acceptance criterion is not literally met, and 4.2's invariant "`failure_reason` null iff confidence `high`" would have to be relaxed. Rejected. |
| D | Migration `0003` relaxing `heal_attempts_status_matches_confidence` so `needs_review`+`high` is legal. | Loosens a constraint that encodes a project invariant, and puts `spec/DESIGN.md`'s schema out of date. Explicitly rejected — see the Risks section of plan 4.2. |

Recommendation: **A**.

### Q3 — Which repository does the PR target, and how is it identified?

| Option | Trade-off |
| --- | --- |
| **A (recommended)** `GITHUB_REPOSITORY` env var, `owner/repo`, plus `GITHUB_TOKEN` and optional `GITHUB_BASE_BRANCH` (default `main`). | Explicit, matches the GitHub Actions convention the "Future Features" section is heading toward, and is trivially overridable in tests. |

### Q4 — Branch naming and duplicate PRs across re-runs

| Option | Trade-off |
| --- | --- |
| **A (recommended)** Branch name is unique per attempt: `mend/heal/<spec-slug>-<first 8 hex of attempt uuid>`. ## Architectural decisions already made (do not revisit)

1. **The patched source is recomputed, never stored.** `applySelectorSubstitution` is
   deterministic and was already used by `run_single_test` on the same original source, so the
   recomputed source is byte-identical to the one that was executed and passed. If the spec on
   disk has since changed, the substitution fails and no PR is opened — which is the correct
   conservative behaviour.

2. **Delivery is injected, not imported.** `runHeal` gains an optional `openPullRequest`
   function, exactly as it already takes `model`, `createToolbox`, and `readSpecSource`.
   `runner/heal-run.ts` must **not** import `@octokit/rest`, `createOctokitApi`, or
   `resolveGitHubConfig`. Only `runner/cli/heal-run.cli.ts` wires the real one.

3. **Disabled ≠ failed.** When no `openPullRequest` is supplied (no `GITHUB_TOKEN`, or
   `--no-pr`), behaviour is **byte-identical to Task 4.2**: high-confidence attempts settle as
   `healed`/`high` with `pr_url IS NULL`. This is not a delivery failure and must never demote
   an attempt to `needs_review`. Every existing test in
   `runner/__tests__/heal-run.integration.spec.ts` passes no opener and must keep passing
   unchanged.

4. **`PullRequestOpener` never throws.** It returns a discriminated `PullRequestOutcome`. The
   heal run's per-attempt `catch` block (the stranding path from 4.2) must not be the thing
   that handles a GitHub error.

5. **The PR body contains no model prose.** It is built from `HealResult` facts:
   selectors, verification summary, changed lines, measured match count, tool-call records
   (`tool`, `arguments`, `resultSummary`). `transcript.messages`, `contentPreview`, and
   `modelRequests` are never read. The gate is not model-scored and neither is the PR's
   justification.

6. **One commit, one file.** The tree contains exactly one entry: the spec file. No lockfile,
   no README, no formatting.

7. **The token is never printed.** Every error message that leaves `runner/github-pr.ts` is
   passed through a redactor that replaces the token with `***`.

8. **No new npm script and no new Playwright config.** `runner/__tests__/*.spec.ts` already
   run under `npm run test:runner`; `db/__tests__/*.spec.ts` already run under `npm run test:db`.

## Implementation steps

### 1. `runner/pr-content.ts`

**The complete runtime import list for this file is exactly these two lines:**

```ts
import { applySelectorSubstitution } from '../agent/tools/spec-edit.js';
import { checkAssertionIntegrity, diffChangedLines } from '../agent/tools/assertion-integrity.js';
```

plus type-only imports from `../agent/loop/confidence.js` and
`../agent/tools/assertion-integrity.js`, and the value import of `TOOL_CALL_COUNT_CEILING`
from `../db/schema-contract.js`. **Do not import from `../agent/tools/run-single-test.js`**
even though it re-exports these names: that module runs
`createRequire(import.meta.url).resolve('playwright')` at import time and would drag Playwright
resolution into a pure module.

Export the constants and functions listed in **Interfaces / types**. Behaviour, exactly:

`sanitiseOneLine(text: string, maxChars: number): string`
- Replace every ASCII control character (`/[ -]/g`) with a single space.
- Collapse runs of whitespace to one space, then `trim()`.
- If the result is longer than `maxChars`, return `result.slice(0, maxChars - 1) + '…'`.

`slugifySpecFile(specFile: string): string`
- Take the substring after the last `/` (or the whole string if none).
- Strip a trailing `.spec.ts`, else a trailing `.ts`, if present.
- Lowercase, replace `/[^a-z0-9]+/g` with `-`, strip leading and trailing `-`.
- Clamp to 40 characters, strip a trailing `-` again.
- If the result is empty, return `'spec'`.

`buildBranchName(specFile: string, attemptId: string): string`
- `` `${PR_BRANCH_PREFIX}/${slugifySpecFile(specFile)}-${attemptId.replace(/-/g, '').slice(0, 8)}` ``
- If `attemptId.replace(/-/g, '')` is empty, use `'00000000'`.

`buildPrTitle(assessment: HealAssessment): string`
- `` `fix(e2e): heal selector in ${basenameOf(specFile)}` ``, then `sanitiseOneLine(…, 120)`.
- `basenameOf` is the same "substring after the last `/`" rule as above; define it as a local
  non-exported helper.

`buildCommitMessage(assessment: HealAssessment): string`
- Exactly (with a real blank line after the subject):
  ```
  fix(e2e): heal selector in <specFile>

  Replace <originalSelector> with <proposedSelector> in test "<testName>".
  Verified by re-executing the single affected test; assertion integrity checked.
  ```
- Every interpolated value goes through `sanitiseOneLine(value, 200)` first.

`buildUnifiedDiff(specFile: string, changedLines: readonly SpecLineChange[]): string`
- Header two lines: `--- a/<specFile>` and `+++ b/<specFile>`.
- Then, for each change in order: `@@ -<n>,1 +<n>,1 @@`, then `-<before>`, then `+<after>`,
  where `<n>` is `change.lineNumber`.
- Join every line with `\n` and append a trailing `\n`.
- No context lines. This diff is for display in the PR body only; it is never applied.

`buildPatch(assessment, originalSource, checkIntegrity = checkAssertionIntegrity): PatchResult`

The third parameter exists **only** so the integrity branch is unit-testable; production callers
must never pass it. Body, exactly:

1. `const selector = assessment.result.proposedSelector;`
   if `selector === null` → `{ ok: false, code: 'substitution-failed', message: 'no proposed selector' }`.
2. `const sub = applySelectorSubstitution(originalSource, assessment.result.originalSelector, selector);`
   if `!sub.ok || sub.proposedSource === null || sub.fromLiteral === null || sub.toLiteral === null`
   → `{ ok: false, code: 'substitution-failed', message: `${sub.failure ?? 'unknown'}: ${sub.detail}` }`.
3. `const integrity = checkIntegrity(originalSource, sub.proposedSource, { fromLiteral: sub.fromLiteral, toLiteral: sub.toLiteral });`
   if `!integrity.ok` →
   `{ ok: false, code: 'assertion-integrity', message: integrity.violations.map((v) => `${v.rule}: ${v.detail}`).join('; ') }`.
   **This step is non-negotiable and must run before any value is returned with `ok: true`.**
4. `const changedLines = diffChangedLines(originalSource, sub.proposedSource);`
   if `changedLines.length === 0` →
   `{ ok: false, code: 'no-changed-lines', message: 'proposed source is identical to the original' }`.
5. Otherwise `{ ok: true, proposedSource: sub.proposedSource, fromLiteral: sub.fromLiteral,
   toLiteral: sub.toLiteral, changedLines, diff: buildUnifiedDiff(assessment.result.specFile, changedLines) }`.

`buildPrBody(input: PrBodyInput): string`

Build these sections, in this order, separated by a blank line. The `##` headings are literal
and the Reviewer greps for them.

```
## Summary

An automated selector fix produced by Self-Healing E2E Tests.

| Field | Value |
| --- | --- |
| Spec file | `<specFile>` |
| Test | `<testName>` |
| Original selector | `<originalSelector>` |
| Proposed selector | `<proposedSelector>` |
| Branch | `<branch>` -> `<baseBranch>` |

## Verification

The single affected test was re-executed against a temporary copy of the spec file and passed.
A fix is never accepted on the model's word alone.

- executed: <verification.executed>
- passed: <verification.passed>
- duration: <verification.durationMs>ms

<fenced block, language `text`, containing the clamped verification output>

## Assertion integrity

The proposed spec was diffed against the original and re-checked before this commit was
created. No assertion was removed, weakened, skipped, or marked `.only`.

Changed lines:

| Line | Before | After |
| --- | --- | --- |
| <n> | `<before>` | `<after>` |

## Confidence

Confidence is derived from observable signals only, never from the model's self-report.

- level: high
- measured DOM matches for the proposed selector: <measurement.matchCount>
- model-initiated tool calls: <result.toolCallCount>

## Agent tool calls

1. `<tool>` — args `<compact JSON of arguments>` -> <resultSummary, one line>
2. …

## Diff

<fenced block, language `diff`, containing the unified diff>
```

Then `PR_FOOTER` as the final line.

Rules for the body:
- The verification output is `sanitiseOutput(assessment.result.verification?.output ?? '')`,
  where `sanitiseOutput` is a local non-exported helper that replaces every occurrence of three
  consecutive backticks with `'` and clamps to `MAX_PR_OUTPUT_CHARS` by keeping the **last**
  `MAX_PR_OUTPUT_CHARS` characters prefixed with `…[output truncated]…\n`.
- If `assessment.result.verification === null`, print `- executed: false`, `- passed: false`,
  `- duration: 0ms` and an empty fenced block. (`assertPrEligible` makes this unreachable; the
  branch exists so the file compiles under `strict`.)
- If `assessment.measurement === null`, print `-` for the match count. (Also unreachable.)
- Table cell text goes through `sanitiseOneLine(value, 200)` and then has every `|` replaced by
  `\|`.
- The tool-call list is `assessment.result.transcript.toolCalls` in order, at most
  `TOOL_CALL_COUNT_CEILING` entries; `arguments` is rendered with
  `JSON.stringify(record.arguments)` clamped to 200 chars and `resultSummary` through
  `sanitiseOneLine(record.resultSummary, 300)`. If the list is empty, print
  `_No tool calls were recorded._`.
- `transcript.messages`, `transcript.modelRequests`, and `contentPreview` are **never** read.
- Finally clamp: if `body.length > MAX_PR_BODY_CHARS`, return
  `body.slice(0, MAX_PR_BODY_CHARS - PR_TRUNCATION_SUFFIX.length) + PR_TRUNCATION_SUFFIX`,
  where `PR_TRUNCATION_SUFFIX = '\n\n…[body truncated]…\n\n' + PR_FOOTER` (a non-exported
  module constant). The footer must survive truncation.

### 2. `runner/github-pr.ts`

Imports permitted: `node:fs/promises` (`readFile`), `node:path`, `node:url`,
`@octokit/rest` (inside `createOctokitApi` only), `./pr-content.js`, and value + type imports

**2a. Config.**

```ts
export const DEFAULT_BASE_BRANCH = 'main';
const REPOSITORY_PATTERN = /^[A-Za-z0-9._-]+\/[A-Za-z0-9._-]+$/;
```

`resolveGitHubConfig(env: NodeJS.ProcessEnv): GitHubConfig | null`
1. `const token = (env.GITHUB_TOKEN ?? '').trim();` if empty → **return `null`** (delivery
   disabled — not an error).
2. `const repository = (env.GITHUB_REPOSITORY ?? '').trim();` if empty → `throw new
   GitHubConfigError('GITHUB_REPOSITORY is not set; expected "owner/repo"')`.
3. If `!REPOSITORY_PATTERN.test(repository)` → `throw new GitHubConfigError('GITHUB_REPOSITORY
   must be "owner/repo"')`.
4. `const [owner, repo] = repository.split('/');` (guard both with `?? ''` for
   `noUncheckedIndexedAccess`; they are non-empty by the pattern).
5. `const baseBranch = (env.GITHUB_BASE_BRANCH ?? '').trim() || DEFAULT_BASE_BRANCH;`
6. Return `{ token, owner, repo, baseBranch }`.

`GitHubConfigError extends Error` with `name = 'GitHubConfigError'`.

**2b. `readSpecFileFromDisk(specFile: string): Promise<string>`**
- `const repoRoot = resolve(dirname(fileURLToPath(import.meta.url)), '..', '..');`
- `return readFile(resolve(repoRoot, specFile), 'utf8');`
- It **throws** on failure (unlike `readSpecSourceFromDisk` in `heal-queue.ts`, which returns
  `null` and clamps). Do not reuse `readSpecSourceFromDisk` here: its clamping would corrupt the
  committed file.

**2c. `createOctokitApi(config: GitHubConfig): GitHubApi`**

The only place `@octokit/rest` appears in the repository.

```ts
const octokit = new Octokit({ auth: config.token });
```

Map each `GitHubApi` method to exactly one Octokit call:

| `GitHubApi` method | Octokit call | Returns |
| --- | --- | --- |
| `getRef({ owner, repo, ref })` | `octokit.rest.git.getRef({ owner, repo, ref })` | `{ sha: res.data.object.sha }` |
| `getCommit({ owner, repo, commitSha })` | `octokit.rest.git.getCommit({ owner, repo, commit_sha: commitSha })` | `{ treeSha: res.data.tree.sha }` |
| `createTree({ owner, repo, baseTreeSha, path, content })` | `octokit.rest.git.createTree({ owner, repo, base_tree: baseTreeSha, tree: [{ path, mode: '100644', type: 'blob', content }] })` | `{ sha: res.data.sha }` |
| `createCommit({ owner, repo, message, treeSha, parentSha })` | `octokit.rest.git.createCommit({ owner, repo, message, tree: treeSha, parents: [parentSha] })` | `{ sha: res.data.sha }` |
| `createRef({ owner, repo, ref, sha })` | `octokit.rest.git.createRef({ owner, repo, ref, sha })` | `void` |
| `createPullRequest({ owner, repo, title, body, head, base })` | `octokit.rest.pulls.create({ owner, repo, title, body, head, base })` | `{ url: res.data.html_url, number: res.data.number }` |

No `try`/`catch` inside `createOctokitApi` — errors propagate to `createPullRequestOpener`,
which is the single place they are converted into an outcome.

**2d. `redactToken(text: string, token: string): string`** — non-exported helper.
`token.length === 0 ? text : text.split(token).join('***')`.

**2e. `createPullRequestOpener(deps: PullRequestOpenerDeps): PullRequestOpener`**

Returns an `async (request) => { … }` closure that **never throws**. Body, exactly, in this
order:

1. `try { assertPrEligible(request.assessment); } catch (error) { return { ok: false, code:
   'not-pr-eligible', message: messageOf(error) }; }`
2. `let originalSource: string; try { originalSource = await deps.readSpecFile(
   request.assessment.result.specFile); } catch (error) { return { ok: false, code:
   'spec-unreadable', message: messageOf(error) }; }`
3. `const patch = buildPatch(request.assessment, originalSource);` — **two arguments only**.
   `if (!patch.ok) { return { ok: false, code: patch.code, message: patch.message }; }`
4. `const branch = buildBranchName(request.assessment.result.specFile, request.attemptId);`
5. Inside one `try { … } catch (error) { return { ok: false, code: 'github-api-error',
   message: redactToken(messageOf(error), deps.config.token) }; }`:
   a. `const base = await deps.api.getRef({ owner, repo, ref: `heads/${deps.config.baseBranch}` });`
   b. `const baseCommit = await deps.api.getCommit({ owner, repo, commitSha: base.sha });`
   c. `const tree = await deps.api.createTree({ owner, repo, baseTreeSha: baseCommit.treeSha,
      path: request.assessment.result.specFile, content: patch.proposedSource });`
   d. `const commit = await deps.api.createCommit({ owner, repo,
      message: buildCommitMessage(request.assessment), treeSha: tree.sha, parentSha: base.sha });`
   e. `await deps.api.createRef({ owner, repo, ref: `refs/heads/${branch}`, sha: commit.sha });`
   f. `const pr = await deps.api.createPullRequest({ owner, repo,
      title: buildPrTitle(request.assessment),
      body: buildPrBody({ assessment: request.assessment, diff: patch.diff,
        changedLines: patch.changedLines, branch, baseBranch: deps.config.baseBranch }),
      head: branch, base: deps.config.baseBranch });`
   g. `deps.logger?.(\`[pr] created ${pr.url}\`);`
   h. `return { ok: true, prUrl: pr.url, prNumber: pr.number, branch, headSha: commit.sha };`
6. `messageOf(error)` is `error instanceof Error ? error.message : String(error)`, defined as a
   local non-exported helper.

Exactly six API calls on the success path. No loop, no retry, no `setTimeout`, no
`Promise.all`.

## Risks

**Q1 is a real trade-off, not a formality.** Under the recommended option the `confidence`
column can read `'low'` for a fix the gate graded `high`, purely because GitHub was down. If
the human considers that unacceptable, say so **before** the Builder starts: option C (keep the
row `healed`/`high`, leave `pr_url` NULL, express "needs review" as a query) is a small change
to `runner/heal-run.ts` plus a relaxation of 4.2's "failure_reason null iff high" invariant —
but it will fail a literal reading of the task's acceptance criterion.

**`agent/tools/run-single-test.ts` executes work at import time.** It calls
`createRequire(import.meta.url).resolve('playwright')` at module scope. Importing
`applySelectorSubstitution` or `diffChangedLines` *from that module* (it re-exports both) would
make `runner/pr-content.ts` depend on Playwright resolution and could break the pure unit
tests. Import from `agent/tools/spec-edit.js` and `agent/tools/assertion-integrity.js`
directly, as the plan specifies.

**`readSpecSourceFromDisk` clamps.** `agent/loop/heal-queue.ts`'s reader passes the source
through `clampSpecSource` for prompt budgeting. Committing a clamped file would truncate the
test. `readSpecFileFromDisk` in `runner/github-pr.ts` must be a separate, unclamped read. Do
not "reuse" the existing helper.

**The injected integrity checker is a test seam, not a feature.** If the Builder finds itself
passing a third argument to `buildPatch` from `runner/github-pr.ts`, that is a defect: the
production path must use the default. The acceptance criteria check this by grep.

**The spec on disk may have drifted since the heal ran.** If it has,
`applySelectorSubstitution` returns `selector-not-found` or `selector-ambiguous` and the opener
returns `substitution-failed`. Under Q1's option A that settles the attempt as `needs_review`
with the fix recorded. This is correct: committing a patch derived from a source that was never
executed would break the verification guarantee. Do not "fix" it by fetching the file from
GitHub and patching that instead.

**`npm install` may fail in a sandbox.** If `@octokit/rest` cannot be installed, report
**"Blocked: cannot install @octokit/rest"** and stop. Do not substitute a hand-rolled `fetch`
client — that is Q2 option B and needs a `DESIGN.md` amendment the Architect has not written.

**Octokit's response typing.** `res.data.object.sha`, `res.data.tree.sha`, and
`res.data.html_url` are all present on the documented responses, but `@octokit/rest`'s types are
generated and occasionally awkward under `strict` + `noUncheckedIndexedAccess`. If a field is
typed as optional, guard it and `throw new Error('unexpected GitHub response: …')` — the
surrounding `try` converts that into `github-api-error`. Do not use `any`, and do not add
`// @ts-expect-error`.

**Branch names with slashes.** `mend/heal/<slug>-<id>` contains slashes, which is legal for a
Git ref and for `createRef`'s `refs/heads/…`, but the `head` parameter of `pulls.create` must be
the branch name **without** the `refs/heads/` prefix (and without an `owner:` prefix, since the
head is in the same repository). Getting this wrong produces a 422. Test 10 pins it.

**A `CHECK` constraint rejects a write.** `heal_attempts_pr_url_requires_high_confidence` and
`heal_attempts_status_matches_confidence` encode the project's invariants at rest. If either
fires, the mapping is wrong, not the constraint. Do not write a migration to loosen it —
escalate to the Architect.

**The live check opens a real pull request.** It is deliberately gated behind explicit human
instruction. A Builder that runs it unprompted has created a real artifact in a real repository
that a human must clean up. Do not run it to "check the work".

**PR body size.** GitHub rejects bodies over 65536 characters. `MAX_PR_BODY_CHARS = 60_000`
leaves headroom, and the verification output is clamped to 4 000 characters before that. If the
live run still gets a 422 on `pulls.create`, report it — do not raise the constant.

**Temptation to make the failure path "smarter".** Re-queuing a failed delivery, opening the PR
later, or writing a "pending delivery" table are all out of scope and all reintroduce unbounded
work. The recorded `needs_review` row with the selector and transcript intact is the complete,
intended answer.
