# Plan: 4.2 — Persist runs and attempts

## Goal

After this task, a single command (`npm run heal`) classifies a Playwright results file,
heals every selector-drift failure, and writes the whole thing to PostgreSQL: one `test_runs`
row per invocation and one `heal_attempts` row per failure sent to the agent. Each attempt row
is **inserted before the agent starts**, in status `investigating`, and committed immediately —
so a crash, a kill, or a thrown invariant leaves a visible `investigating` row rather than
nothing. When the attempt settles, exactly one terminal `UPDATE` writes status, confidence,
proposed selector, tool-call count, failure reason, and the full agent transcript as queryable
`jsonb`. Failed and needs_review attempts are persisted on exactly the same path as healed
ones. Nothing in this task opens a PR or writes `pr_url` (Task 5.1), and the verification gate
is untouched: persistence reads the `HealAssessment` that Phase 3 already produced and never
influences it.

---

## Read this before you start: the four ways to ruin this task

**1. Making persistence able to change a verdict.** The repository layer is write-only with
respect to healing. It takes a finished `HealAssessment` and maps it to columns. It never
re-derives confidence, never picks a status, never re-runs a test, and never decides whether a
fix is valid. If you find yourself writing `if (passed) confidence = 'high'`, stop — that logic
already exists in `agent/loop/confidence.ts` and must not be duplicated.

**2. Wrapping the heal loop in a database transaction.** The `investigating` row must be
committed *before* the agent runs, or the crash-visibility requirement is false. `pg.Client` is
autocommit unless you issue `BEGIN`. Do not issue `BEGIN` anywhere in `runner/` or
`db/repository.ts`.

**3. Modifying `agent/`.** Every file under `agent/` is finished and reviewed. At the end of
this task `git diff HEAD --name-only -- agent/ tests/ app-under-test/ breakage/ db/migrations/`
must print nothing. `runner/` calls the existing exported functions as they are. If you believe
you need a new export from `agent/`, stop and report **"Blocked: plan requires a change to
`agent/`"**.

**4. Writing a migration.** `db/migrations/0001_*.sql` and `0002_*.sql` are applied and
checksummed. Editing either one produces a `checksum-mismatch` error. This task adds **no**
migration file. If a `CHECK` constraint rejects one of your writes, the write is wrong, not the
constraint — see Risks.

### Q1 — Where does the persistence wiring live? (`TASKS.md` is silent; `DESIGN.md` implies it)

`TASKS.md` 4.2 says only "Persist runs and attempts". But "every attempt persisted" is not
verifiable without a caller that produces attempts. `DESIGN.md`'s architecture diagram shows
`npm run heal` → **Runner** → {Playwright, Heal Agent, PostgreSQL, GitHub API}, and `CLAUDE.md`
names `runner/` as a spec-referenced directory. No task in `TASKS.md` explicitly creates it.

| Option | What it means | Trade-off |
| --- | --- | --- |
| **A (recommended)** | Create a thin `runner/` (`runner/heal-run.ts` + `runner/cli/heal-run.cli.ts`, script `npm run heal`) that classifies → heals → persists. | Matches `DESIGN.md`'s architecture literally, leaves `agent/` untouched, and gives Task 5.1 an obvious place to hook PR creation in (after `settleHealAttempt`, gated on `prEligible`). The runner is ~150 lines of orchestration with no new logic. |
| B | Add persistence to `agent/loop/cli/heal-all.cli.ts`. | That CLI is the Task 3.3 scenario-matrix *verification harness*: it runs the queue up to 5 times and exits 3 when the matrix fails. Persisting its rows would mix regression-harness runs with real heal runs and corrupt Phase 7's heal-rate denominator. Rejected. |
| C | Add `onAttemptStart` / `onAttemptSettled` hooks to `healQueueSequentially`. | Puts database concerns inside the agent and requires modifying reviewed Phase-3 code. Rejected. |

Recommendation: **A**. The runner does **not** execute Playwright itself — it reads the existing
`test-results/results.json`, exactly like `heal:one` and `heal:all` do. Running the suite stays
`npm run test:e2e`.

### Q2 — Are non-selector-drift failures (`report.skipped`) persisted as `heal_attempts`?

`REQUIREMENTS.md` says non-selector failures are "detected and skipped, not healed";
`TASKS.md` 3.1 says they are "skipped and recorded, never sent to the model".

| Option | Trade-off |
| --- | --- |
| **A (recommended)** No `heal_attempts` row. Counted in the run report as `skipped` and printed by the CLI. | A skipped failure is not a heal *attempt* — no agent ran, no tool was called. Persisting it as `status='failed'` would inflate Phase 7's denominator and make the headline heal-rate metric wrong. They remain recorded in the classifier report and in the CLI output. |
| B | Insert a row with `status='failed'`, `confidence='none'`, `failure_reason='not-selector-drift'`. | Satisfies a loose reading of "recorded", but silently changes what "X% of selector-drift failures healed" means. |

Recommendation: **A**.

### Q3 — Is `DATABASE_URL` required by `npm run heal`?

| Option | Trade-off |
| --- | --- |
| **A (recommended)** Required. Unset → stderr message, exit 1, nothing runs. | "Never silently absent" is the whole point of 4.2. A run that silently heals without persisting is the exact failure mode the criterion forbids. |
| B | Optional, persistence skipped when unset. | Creates a mode where attempts vanish. Rejected. |

Recommendation: **A**.

### Q4 — What exactly goes in the `transcript` jsonb, and what if it is enormous?

`DESIGN.md`: "`transcript` holds the ordered list of tool calls, their arguments, and their
results. It is what the dashboard detail view replays." Task 6.2 additionally needs the DOM the
agent saw and the test output per step.

Recommendation: store a **versioned envelope** (`PersistedTranscript`, see Interfaces) wrapping
the full `HealTranscript` plus the outcome metadata that has no column of its own
(`stopReason`, `verification`, `measurement`, `signals`, `reasons`). Guard the size with a
single deterministic two-pass truncation (`MAX_TRANSCRIPT_BYTES = 2_000_000`): pass 1 is the
untouched envelope; if it exceeds the cap, pass 2 clamps every string value deeper than
`TRUNCATED_FIELD_CHARS = 4_000` and replaces `transcript.messages` with `[]`, setting
`truncated: true`. A write is never abandoned because of size. Alternative rejected: storing
only `toolCalls` — Task 6.2 could not then show the DOM the agent saw.

## Implementation steps

### 1. `db/transcript.ts`

Export the constants and functions listed in **Interfaces / types**. Behaviour, exactly:

`clampDeep(value: unknown, maxChars: number): unknown` — recursive, pure:
- `string` longer than `maxChars` → `value.slice(0, maxChars) + '…[truncated]'`; otherwise
  returned unchanged.
- `Array` → new array of `clampDeep(item, maxChars)`, same order, same length.
- non-null `object` → new plain object with the same keys **in the same insertion order**, each
  value `clampDeep`ped.
- everything else (number, boolean, null, undefined) → returned unchanged.

`buildTranscriptEnvelope(assessment: HealAssessment): PersistedTranscript` — pure, no
truncation. Fields come from `assessment` and `assessment.result` verbatim (see the type). Set
`schemaVersion: TRANSCRIPT_SCHEMA_VERSION`, `truncated: false`.

`serialiseTranscript(assessment: HealAssessment): SerialisedTranscript` — the two passes:
1. `const full = buildTranscriptEnvelope(assessment); const json = JSON.stringify(full);`
   If `Buffer.byteLength(json, 'utf8') <= MAX_TRANSCRIPT_BYTES`, return
   `{ json, byteLength, truncated: false }`.
2. Otherwise build `reduced` = the envelope with `transcript.messages` replaced by `[]`, then
   `clampDeep(reduced, TRUNCATED_FIELD_CHARS)`, then set `truncated: true` on the result object
   (set it **after** clamping so the boolean is not touched). Serialise and return
   `{ json, byteLength, truncated: true }` regardless of the resulting size.

`serialiseTranscript` must never throw for a well-formed `HealAssessment`. `JSON.stringify`
cannot cycle here — every type involved is a plain data tree.

### 2. `db/repository.ts`

Imports permitted: `pg` types, `./client.js`, `./transcript.js`, `./schema-contract.js`, and
**type-only** imports from `../agent/loop/confidence.js` and `../agent/loop/types.js`, plus the
**value** import `assertConfidenceInvariant` from `../agent/loop/confidence.js`.
`agent/loop/confidence.ts` has only type-only imports of its own, so this pulls no browser or
OpenAI code into `db/`. Do not import anything from `agent/loop/heal-loop.js`,
`agent/loop/playwright-toolbox.js`, or `agent/loop/openai-client.js`.

Declare `PersistenceError` and `PersistenceErrorCode` as in **Interfaces / types**.

`connectRunClient(connectionString: string, schema?: string): Promise<PgClient>`
1. Throw `PersistenceError('missing-connection-string', ...)` if `connectionString.trim() === ''`.
2. `const client = createDbClient(connectionString); await client.connect();`
3. If `schema !== undefined`: throw `PersistenceError('invalid-schema-name', ...)` when
   `!isValidSchemaName(schema)`, else `await client.query('SET search_path TO "' + schema + '"')`.
   Never `CREATE SCHEMA` here.
4. Return the client. On any error after `connect()`, `await client.end()` before rethrowing.

`insertTestRun(client, input): Promise<string>` — exactly this SQL, parameterised:
```sql
INSERT INTO test_runs (started_at, total, passed, failed)
VALUES ($1, $2, $3, $4)
RETURNING id
```
Before querying, throw `PersistenceError('invariant-violation', ...)` unless
`total >= 0 && passed >= 0 && failed >= 0 && passed + failed <= total`. Return
`rows[0].id`; throw `PersistenceError('query-failed', ...)` if `rows[0]` is undefined
(`noUncheckedIndexedAccess` requires the guard anyway).

`finishTestRun(client, testRunId, finishedAt): Promise<void>`:
```sql
UPDATE test_runs SET finished_at = $2 WHERE id = $1
```
Throw `PersistenceError('not-found', ...)` if `rowCount !== 1`.

`insertHealAttempt(client, input): Promise<string>`:
```sql
INSERT INTO heal_attempts (test_run_id, spec_file, test_name, original_selector)
VALUES ($1, $2, $3, $4)
RETURNING id
```
Every other column takes its schema default: `confidence='none'`, `tool_call_count=0`,
`status='investigating'`, `transcript='{}'`, `pr_url=NULL`, `proposed_selector=NULL`,
`created_at=now()`. **Do not list those columns in the INSERT.** Return `rows[0].id` with the
same guard as above.

`settleHealAttempt(client, input): Promise<void>`:
```sql
UPDATE heal_attempts
   SET status = $2,
       confidence = $3,
       proposed_selector = $4,
       tool_call_count = $5,
       failure_reason = $6,
       transcript = $7::jsonb
 WHERE id = $1 AND status = 'investigating'
```
- Bind `$7` as the **JSON string** from `serialiseTranscript`, not as a JS object.
- `pr_url` is deliberately absent from the SET list. Do not add it.
- The `AND status = 'investigating'` clause makes settling idempotency-safe: a terminal row can
  never be overwritten.
- Before querying, throw `PersistenceError('invariant-violation', ...)` if any of:
  `input.status === 'investigating'`;
  `input.toolCallCount < 0 || input.toolCallCount > TOOL_CALL_COUNT_CEILING`;
  `(input.proposedSelector === null) !== (input.confidence === 'none')`;
  the pair `(status, confidence)` is not one of `('healed','high')`, `('needs_review','low')`,
  `('failed','none')`.
- After querying, throw `PersistenceError('not-found', ...)` if `rowCount !== 1`.

`toSettleInput(attemptId: string, assessment: HealAssessment): SettleHealAttemptInput`:
1. `assertConfidenceInvariant(assessment)` first — a self-contradictory assessment must never
   reach SQL.
2. Return
   `{ attemptId, status: assessment.status, confidence: assessment.confidence,
      proposedSelector: assessment.result.proposedSelector,
      toolCallCount: assessment.result.toolCallCount,
      failureReason: assessment.failureReason,
      transcriptJson: serialiseTranscript(assessment).json }`.
3. No other derivation. Do not recompute confidence, do not clamp `toolCallCount`.

### 3. `runner/heal-run.ts`

Exports `runHeal(options: HealRunOptions): Promise<HealRunReport>` and the types in
**Interfaces / types**. Sequence, exactly:

1. `const startedAt = new Date().toISOString(); const t0 = Date.now();`
2. `const report = await classifyResultsFile(options.resultsPath);` — let a throw propagate.
   No database connection exists yet, so nothing is half-written.
3. `const queue = options.specFilter === undefined ? report.healQueue
      : report.healQueue.filter((f) => f.specFile === options.specFilter);`
4. `const client = await connectRunClient(options.connectionString, options.schema);`
   Everything from here to step 9 is inside `try { … } finally { await client.end(); }`.
5. `const testRunId = await insertTestRun(client, { startedAt, total: report.totalTests,
      passed: report.totalTests - report.failedTests, failed: report.failedTests });`
   Log `run ${testRunId} total=… passed=… failed=… queued=${queue.length} skipped=${report.skipped.length}`.
6. For each `failure` of `queue`, in order:
   a. `const attemptId = await insertHealAttempt(client, { testRunId, specFile: failure.specFile,
        testName: failure.testName, originalSelector: failure.selector ?? '' });`
      Log `[attempt] ${attemptId} spec=${failure.specFile} status=investigating`.
      A throw here propagates (the database is unusable; do not continue).
   b. Inside `try { … } catch (error) { … }`:
      - `const queueResult = await healQueueSequentially([failure], { model: options.model,
           appUrl: options.appUrl, createToolbox: options.createToolbox,
           readSpecSource: options.readSpecSource });`
      - `const assessment = queueResult.assessments[0];` if `undefined`, throw
        `new Error('heal queue returned no assessment')`.
      - `await settleHealAttempt(client, toSettleInput(attemptId, assessment));`
      - push a `PersistedAttempt` with `status: assessment.status`,
        `confidence: assessment.confidence`,
        `proposedSelector: assessment.result.proposedSelector`,
        `toolCallCount: assessment.result.toolCallCount`,
        `prEligible: assessment.prEligible`, `error: null`, and log
        `[settled] ${attemptId} spec=… status=… confidence=… proposed=… toolCalls=… prEligible=…`
        (use `-` for a null selector).
      - `catch`: push a `PersistedAttempt` with `status: 'investigating'`, `confidence: 'none'`,
        `proposedSelector: null`, `toolCallCount: 0`, `prEligible: false`, and
        `error: <message>`. Log `[stranded] ${attemptId} spec=… error=…`. **Do not attempt any
        further UPDATE on that row** — leaving it `investigating` is the required behaviour.
        Continue to the next failure.
7. After the loop: `const finishedAt = new Date().toISOString();
   await finishTestRun(client, testRunId, finishedAt);`
8. Build `totals` with `summariseConfidence` over only the assessments that settled
   successfully. Keep a local `HealAssessment[]` for this.
9. Return the `HealRunReport`.

`runHeal` takes `model`, `createToolbox`, and `readSpecSource` as options so tests can inject
fakes. It must not import `createOpenAIClient` or `createPlaywrightToolbox`.

### 4. `runner/cli/heal-run.cli.ts`

Follow the shape of `agent/loop/cli/heal.cli.ts`, including the trailing `main().catch(...)`.

Flags: `--results=<path>` (default `test-results/results.json`), `--url=<url>` (default
`DEFAULT_APP_URL` from `agent/loop/playwright-toolbox.js`), `--spec=<path>`, `--json`.
Any other flag, or any positional argument → `usage()` to stderr, exit `2`.

Order of operations:
1. Parse args.
2. `const connectionString = resolveDatabaseUrl(process.env);` if `null`, write
   `DATABASE_URL is not set; export it before running npm run heal\n` to stderr and exit `1`.
3. `createOpenAIClient()` inside try/catch; on throw write the message and exit `1`.
4. `await runHeal({ connectionString, resultsPath, appUrl, specFilter, model,
     createToolbox: (failure) => createPlaywrightToolbox(failure, { appUrl }),
     readSpecSource: readSpecSourceFromDisk,
     logger: args.json ? undefined : (line) => process.stdout.write(line + '\n') })`
   inside try/catch; on throw write `Error: ${message}\n` to stderr and exit `1`. Never print a
   stack trace, never print the connection string.
5. Output. With `--json`: `console.log(JSON.stringify(report, null, 2))` and nothing else.
   Without: the `logger` has already streamed the per-attempt lines; then write the final line
   ```
   heal ok: run=<uuid> attempts=<n> healed=<n> needs_review=<n> failed=<n> investigating=<n> (<ms>ms)
   ```
   The four counts are derived from `report.attempts` by `status`.
6. Exit `0` when no attempt has `status === 'investigating'`; otherwise exit `3`. Note that a
   run in which every attempt is `failed` still exits `0` — "no fix found" is a correct outcome,
   not an error.

### 11. `runner/README.md`

Headed sections, all required:
- **What the runner is** — the `DESIGN.md` Runner box; it reads `test-results/results.json`, it
  does not execute the Playwright suite.
- **Command** — `npm run heal`, the four flags, and a worked example.
- **Environment** — `DATABASE_URL` (required), `OPENAI_API_KEY` (required), and the note that

## Risks

**A `CHECK` constraint rejects a write.** The four constraints from Task 4.1 encode the
project's invariants at rest. If `heal_attempts_status_matches_confidence` or
`heal_attempts_selector_requires_verification` fires, the mapping in `toSettleInput` is wrong —
the constraint is not. Do **not** write a migration to loosen it. Escalate to the Architect. The
only legal shapes are `('investigating','none',NULL)`, `('healed','high',<selector>)`,
`('needs_review','low',<selector>)`, `('failed','none',NULL)`. Note that
`deriveConfidence` already guarantees these: it returns `'none'` whenever `proposedSelector` is
null, so a correct mapping cannot violate them.

**`pg` returns `rowCount` as `null`.** Under some `pg` versions `result.rowCount` is typed
`number | null`. Compare with `!==  1` rather than `< 1`, and handle `null` as "not found".

**Enum parameters.** Binding `$2` as a plain string against an `enum` column works in an
`UPDATE ... SET status = $2` because PostgreSQL infers the parameter type from the target
column. If you ever move the enum into a `WHERE` clause or a `SELECT` list, you will need an
explicit `$n::heal_status` cast. Do not add casts speculatively.

**Multi-statement vs parameterised queries.** Every statement in `db/repository.ts` is a single
statement with parameters. Never concatenate a value into SQL. The only interpolation permitted
anywhere in this task is the already-validated schema name in `connectRunClient`, guarded by
`isValidSchemaName`.

**The transcript is bigger than expected.** `HealTranscript.messages` embeds the DOM snapshot
and every tool result, so the envelope can be several times the snapshot size. The two-pass
guard handles it. If you observe truncation firing on the ordinary `app-under-test` scenarios,
report it — that would mean `get_dom_snapshot`'s token ceiling from Task 2.1 is not holding, and
the Architect needs to know.

**Stranded rows accumulate during development.** A `status='investigating'` row is a permanent,
deliberate record that an attempt did not complete. Do not add cleanup, a TTL, or a "reset
stuck attempts" command. Clearing the dev database is the developer's job.

**`classifyResultsFile` path resolution.** It resolves against the repository root computed from
`import.meta.url`, not `process.cwd()`. Pass repository-relative paths from the runner and from
tests; an absolute path also works. Do not reimplement the resolution.

**Test isolation.** Both integration suites must use a throwaway `mend_test_*` schema and drop
it in `afterAll`. If schema isolation cannot be made to work, report **Blocked** — never run
these suites against `public`, and never write `DROP DATABASE` or an unqualified
`DROP SCHEMA public CASCADE`.

**Deterministically stranding an attempt (step 10 assertion 5).** This is the fiddliest test in
the task because `healQueueSequentially` deliberately swallows most errors. If no mechanism
works without touching `agent/`, report **"Blocked: cannot deterministically strand an
attempt"** and stop. Do not weaken or delete the assertion, and do not satisfy it by inserting a
row and never settling it outside the real code path.
