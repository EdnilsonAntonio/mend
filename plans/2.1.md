# Plan: 2.1 — `get_dom_snapshot`

> **Revision 3 (this document supersedes revisions 1 and 2 in full).**
> Two defects in the earlier revisions were found empirically by the Builder and confirmed
> independently by the Reviewer. Both are now resolved by explicit decision, not by
> Builder judgment:
>
> 1. **`pruneDocument` cannot live in a `.ts` file.** `tsx` hardcodes esbuild's
>    `keepNames: true` and routes `.ts` imports through the CJS transform, which injects
>    `__name(fn, "fn")` calls into the body of every named nested function — regardless of
>    `package.json`'s `type` field. Those `__name` calls become
>    `ReferenceError: __name is not defined` inside `page.evaluate`, because the function is
>    re-executed in an isolated browser context. **Decision: the prune implementation is a
>    plain ESM JavaScript file (`agent/tools/dom-prune.js`) with a hand-written
>    `agent/tools/dom-prune.d.ts`, and `package.json` gets `"type": "module"`.** See
>    architectural decision 9. Injecting a `globalThis.__name` shim is explicitly forbidden.
> 2. **`npm run <script>` prepends a banner to stdout** in this environment (npm 11.12.1),
>    so `npm run tool:dom-snapshot -- --json | JSON.parse` fails. That was an unsatisfiable
>    acceptance criterion, and the repo-wide `.npmrc` used to work around it is forbidden.
>    **Decision: the machine-readable CLI contract is direct `npx tsx` invocation; the npm
>    script is a convenience wrapper whose documented form is `npm run --silent`.** See
>    architectural decision 10. `.npmrc` must not exist.
>
> Everything else in this plan (the depth ladder, the token ceiling, the ten tests, the
> README content, the breakage-scenario behaviour) is unchanged and was confirmed correct by
> both review rounds. Do not redesign those parts.

## Goal

After this task the repository can produce a **pruned, token-bounded, re-parseable HTML
snapshot of the app under test**, deterministically and with no OpenAI dependency, from
either (a) a live Playwright `Page` — the form the Phase 3 agent loop will use — or (b) a
bare URL via a single standalone command. Scripts, styles, comments, inline event handlers,
`style=` attributes and all `data-*` attributes are stripped; ids, classes, `role`,
`aria-*`, text content and tree structure are preserved. The snapshot never mutates the
live page. The output for `app-under-test/` is documented and asserted to sit far under a
named token ceiling. This is the first of the three agent tools, and like the other two it
is built and tested before any model is involved.

## Open questions — settled

Q1 and Q2 were answered at the round-1 approval gate; their recommendations were accepted
and are now binding. Q3 has been superseded by architectural decisions 9 and 10. Nothing in
this section is open. The Builder makes **no** decisions here.

### Q1 — What does "at failure point" mean in v1? → **A, accepted**

The tool takes a live Playwright `Page` that the caller has already navigated. A
convenience wrapper launches a browser and navigates to a URL for standalone/CLI use. The
Phase 3 runner re-navigates to the failing test's page rather than resurrecting mid-test
state.

This is faithful for every seeded scenario by inspection: all five specs call
`page.goto('/')` and the only pre-failure actions are `#email`/`#password` `.fill()` calls,
which set the DOM `value` *property*, not markup — so the freshly navigated DOM is
byte-equivalent to the DOM at failure point for scenarios 1–5. It also leaves the page
**live**, which Task 2.2 (`query_selector`) requires.

No Playwright reporter, fixture, or frozen-artifact mechanism is built in this task.

### Q2 — Should `data-testid` survive pruning? → **A, accepted**

Strip **all** `data-*` attributes, with no allowlist exception. This app has zero `data-*`
attributes by hard rule (`app-under-test/README.md`), so an exception would be untestable
here, and adding one to `app-under-test/index.html` would invalidate the whole
self-healing demonstration.

### Q3 — How is TypeScript executed standalone? → **`tsx`, with the constraints in decisions 9 and 10**

`tsx` stays as the devDependency that runs the CLI. It is *not* used for the tool tests
(Playwright transpiles those itself with Babel, which does not have the `__name` problem).
Its one hard constraint — that it mangles function bodies it transpiles — is handled by
decision 9, not by switching runners. `node --experimental-strip-types` and a `tsc` build
step remain rejected.

## Architectural decisions already made (do not revisit)

1. **Pruning happens in the browser, on a clone.** The prune function is passed to
   `page.evaluate()` and operates on `document.documentElement.cloneNode(true)`. It never
   touches the live tree. Rationale: DESIGN.md says Playwright "provides the live DOM
   snapshot", so the snapshot must reflect post-JS state; and cloning makes
   non-mutation trivially provable.

2. **No HTML parser dependency.** No `parse5`, no `cheerio`, no `jsdom`. The browser is
   already the parser.

3. **No tokenizer dependency.** `estimateTokens(text) = Math.ceil(text.length / 4)` is a
   deliberate cheap heuristic. The ceiling is set with large headroom precisely so the
   heuristic's imprecision does not matter. Adding `tiktoken` is scope creep.

4. **The output is produced by an explicit recursive serializer, not by `outerHTML`.**
   Rationale: `outerHTML` on a whitespace-normalized clone yields one unreadable line and
   gives no hook for depth limiting. The serializer is deterministic and fully specified in
   step 3.

5. **Budget enforcement is a fixed depth ladder, never a hard string truncation.** The
   output is always well-formed HTML. If even the shallowest ladder rung exceeds the
   ceiling, the shallowest result is returned with `truncated: true` — validity beats
   budget. The ladder is a fixed-length array; there is no unbounded retry.

6. **Tool tests live outside `tests/`, under their own Playwright config.** `tests/` is the
   frozen five-spec baseline suite; `npm run test:e2e` must keep reporting exactly 5/5, and
   `tests/README.md` codifies invariants ("One `test()` per file") that tool tests would
   violate. Tasks 2.2 and 2.3 add spec files to the same new directory.

7. **No OpenAI tool-schema wrapper in this task.** The JSON tool definition
   (`{ name: "get_dom_snapshot", parameters: {} }`) that the model sees is Phase 3's job.
   This task ships the capability, not the registration.

8. **`<title>` survives.** `<head>` is emptied of `meta`/`link`/`script`/`style` but the
   title is cheap and orienting.

9. **The browser-context prune function is authored as plain JavaScript, and the package is
   ESM.** *(New in revision 3. This is the resolution to Problem 1 and it is binding.)*

   - `agent/tools/dom-prune.js` — plain ESM JavaScript. No TypeScript syntax anywhere in
     it. No imports. Exactly one module-scope declaration: `pruneDocument`.
   - `agent/tools/dom-prune.d.ts` — hand-written ambient declarations for that file:
     `PruneRequest`, `PruneResult`, `pruneDocument`. Contents given verbatim in the
     Interfaces section.
   - `package.json` gains `"type": "module"`. **This explicitly overrides revision 1's
     instruction "Do not add a `type` field".**

   Why: `page.evaluate(fn, arg)` ships `fn.toString()` to an isolated browser context. tsx
   sets esbuild's `keepNames: true` and transpiles `.ts` files through the CJS path, which
   rewrites named nested functions as `__name(f, "f")`. That identifier does not exist in
   the browser, so the evaluated function throws `ReferenceError` at runtime — invisible to
   `tsc --noEmit`. Only the combination *`.js` extension + `"type": "module"`* routes the
   file through tsx's ESM transform, which leaves the body intact. This was verified twice,
   by `Function.prototype.toString()` inspection and by tracing `node_modules/tsx/dist`
   (`keepNames` appears in `index-DQtFPMc2.mjs`).

   Blast radius of `"type": "module"`, checked and accepted: `app-under-test/server.mjs`
   and `breakage/apply.mjs` are already `.mjs` and unaffected; `app-under-test/app.js` is
   loaded by the **browser** via `<script>` and never by Node, so `package.json` `type` is
   irrelevant to it; `tsconfig.json` already declares `"module": "ESNext"`, so ESM is the
   consistent choice; Playwright loads both configs and all `.ts` specs itself. Future
   phases are unaffected or helped (`pg` works through ESM/CJS interop, Octokit is
   ESM-only, Next.js supports `type: module`).

   Costs accepted, deliberately: the body of `dom-prune.js` is not type-checked by
   `tsc --noEmit`, and `dom-prune.d.ts` is a hand-maintained mirror of a three-declaration
   surface. This is bounded — the file is one function, it is exercised by all ten tests
   through the real `page.evaluate` path, and its declaration surface never grows in this
   task.

   **Forbidden alternatives**, each of which was tried or considered and rejected:
   injecting a `globalThis.__name` shim from the Node side (makes `pruneDocument` depend on
   caller-installed global state — a violation of self-containment in substance even if a
   source grep passes); duplicating the function as a template string; adding `allowJs` /
   `checkJs` to `tsconfig.json`; renaming the file back to `.ts`; switching the project to
   CommonJS.

10. **The CLI has two invocation forms, and only the direct one is the machine contract.**
    *(New in revision 3. This is the resolution to Problem 2 and it is binding.)*

    | Form | Contract |
    | --- | --- |
    | `npx tsx agent/tools/cli/get-dom-snapshot.cli.ts [url] [--json]` | **The contract.** stdout is exactly the tool's output — parseable JSON with `--json`, HTML otherwise. This is the form the acceptance criteria are written against and the form a future CI step would use. |
    | `npm run --silent tool:dom-snapshot -- [url] [--json]` | Convenience wrapper. `--silent` suppresses npm's own logging so stdout is again exactly the tool's output. This is the form documented in the README. |
    | `npm run tool:dom-snapshot` (no `--silent`) | **Not a supported machine-readable form.** npm 11 prepends a `> pkg@version script` banner to stdout. That banner is npm's output, not the tool's, and a script cannot suppress it from the inside. |

    Revision 1's acceptance criteria asserted that plain `npm run tool:dom-snapshot`
    produces clean stdout. That was simply wrong and is withdrawn.

    **Forbidden**: a repo-root `.npmrc` (it silences all npm output repo-wide, including
    real `npm install` errors), any `loglevel` configuration, any `--silent` baked into the
    script definition itself, and any code in the CLI that detects or strips a leading
    banner. If `.npmrc` exists in the working tree from a previous round, **delete it**.

### 3. `agent/tools/dom-prune.js`

**Plain JavaScript. ESM. No TypeScript syntax** — no type annotations, no `interface`, no
`as`, no `satisfies`, no generics. Types are documented with JSDoc comments only (which are
non-binding here; the binding types are in `dom-prune.d.ts`).

**Hard constraint (self-containment):** `pruneDocument` is serialized by
`Function.prototype.toString()` and re-evaluated inside the browser by `page.evaluate`. It
must therefore reference **nothing** outside its own body: no imports, no module-scope
constants, no other module-scope functions, and no globals other than the browser globals
`document`, `Node`, `NodeFilter`, `Set`, `Array`, `String`. Every helper is a function
declared *inside* `pruneDocument`. Every tunable arrives through the `req` argument.

The file's entire module scope is: a JSDoc block, `function pruneDocument(req) { ... }`,
and `export { pruneDocument };`. Nothing else.

Behaviour, in this exact order:

1. `const root = document.documentElement.cloneNode(true);`
   Nothing after this line may read or write the live document.
2. **Comments.** Walk `root` with a `TreeWalker` over `NodeFilter.SHOW_COMMENT` and remove
   every comment node.
3. **Removed tags.** Build `const removedTags = new Set(req.removeTags)`. Collect elements
   from `root.querySelectorAll('*')` whose `tagName.toLowerCase()` is in `removedTags` into
   an array first, then call `el.remove()` on each (drops the whole subtree). Collecting
   first avoids mutating a live `NodeList` mid-iteration.
4. **Attributes.** Build `const keepAttrs = new Set(req.keepAttributes)`. For every
   remaining element, iterate a *copy* of its attribute names
   (`Array.from(el.attributes).map((a) => a.name)` — snapshot the list first, because
   mutating `el.attributes` while iterating it skips entries) and for each name
   `n = raw.toLowerCase()`:
   - keep if `keepAttrs.has(n)` or `n.startsWith('aria-')`;
   - otherwise `el.removeAttribute(raw)`.
   For each kept attribute, rewrite its value:
   - if the value, lowercased, starts with `data:` → set it to the literal string `data:`;
   - else if `value.length > req.maxAttributeLength` →
     `value.slice(0, req.maxAttributeLength) + '…'`.
5. **Serialize.** Return `{ html: '<!DOCTYPE html>\n' + serializeElement(root, 0), elementCount }`
   where `elementCount` counts every element actually emitted.

Helpers declared inside `pruneDocument`:

```
const VOID_TAGS = new Set(['area','base','br','col','embed','hr','img','input',
                           'link','meta','param','source','track','wbr']);

escapeText(s)  -> s.replace(/&/g,'&amp;').replace(/</g,'&lt;').replace(/>/g,'&gt;')
escapeAttr(s)  -> escapeText(s).replace(/"/g,'&quot;')

normalizeText(s) -> collapsed = s.replace(/\s+/g, ' ')
                    trimmed   = collapsed.trim()
                    if trimmed === '' -> return null            (drop the node)
                    if trimmed.length > req.maxTextLength
                        -> return trimmed.slice(0, req.maxTextLength) + '…'
                    return trimmed

serializeElement(el, depth) -> string | null
  if (depth > req.maxDepth) return null;
  tag  = el.tagName.toLowerCase()
  attrs = for each attribute in source order: ` ${name}="${escapeAttr(value)}"`, joined
  indent = '  '.repeat(depth)
  elementCount += 1
  if (VOID_TAGS.has(tag)) return `${indent}<${tag}${attrs} />`
  parts = [] ; for each childNode of el.childNodes:
      - ELEMENT_NODE -> serializeElement(child, depth + 1), push if not null
      - TEXT_NODE    -> t = normalizeText(child.nodeValue ?? ''); if t !== null push
                        `${'  '.repeat(depth + 1)}${escapeText(t)}`
      - anything else -> ignore
  if (parts.length === 0) return `${indent}<${tag}${attrs}></${tag}>`
  if (parts.length === 1 && the single child was a TEXT_NODE
      && (indent.length + tag.length + attrs.length + parts[0].trim().length) <= 100)
      return `${indent}<${tag}${attrs}>${parts[0].trim()}</${tag}>`
  return `${indent}<${tag}${attrs}>\n${parts.join('\n')}\n${indent}</${tag}>`
```

`normalizeText` trims. (Revision 1 said "collapse only; do NOT trim" — that was wrong and
is corrected here: the serializer supplies its own indentation, so leading/trailing
whitespace on a text node would corrupt the layout. This is the only behavioural change in
revision 3.)

`elementCount` is a `let` declared inside `pruneDocument` and incremented by
`serializeElement` only for elements it actually emits.

### 4. `agent/tools/get-dom-snapshot.ts`

TypeScript, strict, as before.

```ts
import type { Page } from '@playwright/test';
import { chromium } from '@playwright/test';
import { pruneDocument, type PruneRequest } from './dom-prune.js';
```

The specifier `'./dom-prune.js'` is exact and correct: it now resolves to a real
`dom-prune.js` on disk, typed by the adjacent `dom-prune.d.ts`.

Exported constants:

```ts
export const DOM_SNAPSHOT_TOKEN_CEILING = 4000;

export const DOM_SNAPSHOT_DEPTH_LADDER: readonly number[] = [1000, 24, 16, 12, 10, 8, 6, 4, 2];

export const DEFAULT_DOM_SNAPSHOT_OPTIONS: DomSnapshotOptions = {
  removeTags: ['script','style','noscript','template','svg','canvas','iframe',
               'link','meta','base','object','embed','audio','video'],
  keepAttributes: ['id','class','role','type','name','href','src','alt','title',
                   'placeholder','value','for','disabled','checked','selected',
                   'readonly','required','hidden','tabindex','lang','action',
                   'method','rel','target'],
  maxTextLength: 200,
  maxAttributeLength: 120,
  tokenCeiling: DOM_SNAPSHOT_TOKEN_CEILING,
  depthLadder: DOM_SNAPSHOT_DEPTH_LADDER,
};
```

Note: `data-*` and `style` are absent from `keepAttributes`, so they are stripped by rule,
not by special case. Same for `on*` handlers.

Functions:

```ts
export function estimateTokens(text: string): number {
  return Math.ceil(text.length / 4);
}
```

```ts
export async function getDomSnapshot(
  page: Page,
  overrides?: Partial<DomSnapshotOptions>,
): Promise<DomSnapshot>
```

1. `const options = { ...DEFAULT_DOM_SNAPSHOT_OPTIONS, ...overrides };`
2. Throw if `options.depthLadder.length === 0` with the message
   `depthLadder must contain at least one entry`.
3. Iterate `options.depthLadder` **in order** (fixed-length array — this is the only loop,
   and it is bounded by the ladder's length):
   - build `req: PruneRequest` from `options` with `maxDepth` = the current rung;
   - `const result = await page.evaluate(pruneDocument, req);` — this is the **only**
     `page.evaluate` call in the file. No preparatory `page.evaluate`, no
     `page.addInitScript`, no global shim of any kind.
   - `const estimatedTokens = estimateTokens(result.html);`
   - if `estimatedTokens <= options.tokenCeiling`, return the snapshot with
     `depthLimit: index === 0 ? null : rung` and `truncated: index !== 0`.
   - otherwise remember this result and continue.
4. If no rung fits, return the **last** result computed, with `truncated: true` and
   `depthLimit` set to the last rung. Never hard-truncate the string.
5. `url` is `page.url()`. `capturedAt` is `new Date().toISOString()`.

```ts
export async function captureDomSnapshotFromUrl(
  url: string,
  overrides?: Partial<DomSnapshotOptions>,
): Promise<DomSnapshot>
```

Launches `chromium.launch({ headless: true })`, creates a context and page,
`await page.goto(url, { waitUntil: 'load' })`, calls `getDomSnapshot(page, overrides)`, and
closes the browser in a `finally` block so the browser is closed even on failure. Returns
the snapshot. No retries. No default URL — the caller supplies it.

none is to be added.

### 6. `agent/tools/__tests__/get-dom-snapshot.spec.ts`

Ten tests, using `@playwright/test`. Tests 1–4, 7, 8 build their own DOM with
`page.setContent(...)`; tests 5, 6, 9, 10 hit the live app at `/`.

1. **`strips scripts, styles, comments, inline handlers, and data-* attributes`** —
   `setContent` a document containing `<script>var x=1;</script>`, `<style>.a{color:red}</style>`,
   `<!-- secret -->`, `<div style="color:red" data-payload='{"a":1}' onclick="go()" id="keep">hi</div>`.
   Assert `snapshot.html` contains none of: `<script`, `<style`, `<!--`, `style=`, `data-`,
   `onclick`, `var x=1`, `color:red`, `secret`. Assert it *does* contain `id="keep"` and `hi`.
2. **`preserves ids, classes, roles, aria attributes, and text`** — fixture with
   `<button id="b1" class="btn btn--primary" role="button" aria-label="Close">Sign In</button>`.
   Assert all four attributes and the text `Sign In` appear.
3. **`output re-parses into an equivalent DOM`** — snapshot the app page, then on a second
   page `await page2.setContent(snapshot.html)` and assert
   `await page2.locator('#login-btn').count() === 1` and
   `await page2.locator('#product-card > .product-card__price').count() === 1`.
   This is the operational definition of "valid HTML".
4. **`does not mutate the live page`** — record
   `await page.evaluate(() => document.documentElement.outerHTML)` before and after
   `getDomSnapshot(page)`; assert the two strings are strictly equal.
5. **`app snapshot stays well under the token ceiling`** — `goto('/')`, snapshot; assert
   `snapshot.estimatedTokens <= 1500`, `snapshot.truncated === false`,
   `snapshot.depthLimit === null`, and `snapshot.estimatedTokens <= DOM_SNAPSHOT_TOKEN_CEILING`.
6. **`app snapshot preserves every selector the baseline suite depends on`** — assert
   `snapshot.html` contains each of: `id="email"`, `id="password"`, `id="remember-me"`,
   `id="login-btn"`, `class="add-to-cart"`, `id="nav-home"`, `id="nav-products"`,
   `id="nav-cart"`, `class="product-card__price"`, `id="cart-count"`, `id="login-status"`,
   `id="cart-status"`, `Sign In`, `Add to Cart`, `$149.00`.
7. **`truncates over-long text nodes`** — `setContent` with a `<p>` holding `'x'.repeat(5000)`;
   assert `snapshot.html` contains `…` and does not contain `'x'.repeat(300)`.
8. **`the depth ladder engages when the ceiling is exceeded`** — `goto('/')`, then
   `getDomSnapshot(page, { tokenCeiling: 20 })`; assert `snapshot.truncated === true`,
   `snapshot.depthLimit !== null`, and that its `html` is shorter than the html from an
   un-overridden snapshot of the same page.
9. **`captureDomSnapshotFromUrl works without a test fixture page`** — call
   `captureDomSnapshotFromUrl('http://localhost:3100/')` directly (it launches and closes
   its own browser); assert the result contains `id="login-btn"` and that
   `elementCount > 10`.
10. **`keeps the title and drops head boilerplate`** — `goto('/')`; assert `snapshot.html`
    contains `<title>Acme Store</title>` and contains neither `<meta` nor `<link`.

Use `test.describe` freely here — the `tests/README.md` invariants apply to `tests/` only.

Exactly ten tests. Do not add an eleventh: the self-containment property is verified against
the **tsx** transform in step 9, and Playwright's Babel transform (which these tests run
under) does not exercise the failure mode, so a test here would prove nothing.

```ts
// agent/tools/get-dom-snapshot.ts

export interface DomSnapshotOptions {
  /** Tag names (lowercase) removed with their entire subtree. */
  readonly removeTags: readonly string[];
  /** Attribute names (lowercase) kept. Any `aria-*` attribute is also kept. */
  readonly keepAttributes: readonly string[];
  /** Text nodes longer than this are truncated and suffixed with U+2026. */
  readonly maxTextLength: number;
  /** Attribute values longer than this are truncated and suffixed with U+2026. */
  readonly maxAttributeLength: number;
  /** Estimated-token budget for the serialized snapshot. */
  readonly tokenCeiling: number;
  /** Ordered max-depth rungs tried until the budget is met. Fixed length; no unbounded retry. */
  readonly depthLadder: readonly number[];
}

export interface DomSnapshot {
  /** The page URL the snapshot was taken from. */
  readonly url: string;
  /** Pruned, well-formed HTML. Never truncated mid-string. */
  readonly html: string;
  /** ceil(html.length / 4). A heuristic, not a real tokenizer. */
  readonly estimatedTokens: number;
  /** Number of elements actually emitted into `html`. */
  readonly elementCount: number;
  /** null when the full tree was serialized; otherwise the depth rung that was used. */
  readonly depthLimit: number | null;
  /** True when a depth limit had to be applied to meet the token ceiling. */
  readonly truncated: boolean;
  /** ISO 8601 timestamp. */
  readonly capturedAt: string;
}

export const DOM_SNAPSHOT_TOKEN_CEILING: number;
export const DOM_SNAPSHOT_DEPTH_LADDER: readonly number[];
export const DEFAULT_DOM_SNAPSHOT_OPTIONS: DomSnapshotOptions;

export function estimateTokens(text: string): number;

export function getDomSnapshot(
  page: import('@playwright/test').Page,
  overrides?: Partial<DomSnapshotOptions>,
): Promise<DomSnapshot>;

export function captureDomSnapshotFromUrl(
  url: string,
  overrides?: Partial<DomSnapshotOptions>,
): Promise<DomSnapshot>;
```

## Risks

- **`pruneDocument` closes over something and dies inside the browser.** This remains the
  single most likely failure, and `npm run typecheck` will not catch it. A reference to a
  module-scope `const VOID_TAGS` becomes `ReferenceError: VOID_TAGS is not defined` at
  runtime. Every helper and constant must be declared inside the function body. All ten
  tests exercise the real evaluate path, so `npm run test:tools` catches it immediately. If
  the Builder sees a `ReferenceError` from inside `evaluate`, move the identifier inside the
  function. Do **not** work around it by inlining the whole thing as a template string, and
  do **not** define the missing identifier as a global.

- **Someone renames `dom-prune.js` back to `.ts`.** It will typecheck, it will pass
  `npm run test:tools` (Playwright's Babel transform is clean), and then the CLI will fail
  at runtime with `ReferenceError: __name is not defined` — a confusing split failure. This
  is why the README documents the reason and why the acceptance criteria assert the file
  extension. If the Builder believes `.ts` should work, it must report **Blocked / unclear**
  rather than change the extension.

- **`npm run --silent` does not suppress the banner in this environment.** The plan assumes
  it does (it sets npm's loglevel for that invocation only, which is the documented,
  narrowly-scoped mechanism). If the Builder finds that `npm run --silent tool:dom-snapshot
  -- --json` still emits a banner, it must report **Blocked / unclear** and note that the
  contract-form (`npx tsx`) criteria all pass. It must **not** add a `.npmrc`, must not set
  `loglevel` anywhere, must not bake `--silent` into the script value, and must not add
  banner-stripping code to the CLI. The two `npm run --silent` acceptance criteria are the
  only ones at risk, and the Architect — not the Builder — decides what replaces them.

- **`"type": "module"` breaks something unforeseen.** The blast radius was analysed in
  decision 9 and is believed to be zero, but the proof is empirical: `npm run test:e2e` must
  still report 5 passed and `npm run typecheck` must still exit 0 after the change. If
  either regresses, report **Blocked / unclear** — do not revert `"type": "module"`
  unilaterally, because `dom-prune.js` depends on it.

- **`dom-prune.d.ts` drifts from `dom-prune.js`.** The declarations are a hand-maintained
  mirror. They are given verbatim in the Interfaces section and must be copied exactly; the
  surface is three declarations and does not grow in this task. Any change to
  `pruneDocument`'s parameters requires the same change in both files in the same edit.

- **Mutating `el.attributes` while iterating it.** `NamedNodeMap` is live; removing an
  attribute mid-iteration silently skips the next one, so `style=` or a `data-*` survives
  and an acceptance criterion fails for a non-obvious reason. Snapshot the names into a
  plain array first (step 3.4). The same applies to the live `NodeList` in step 3.3.

- **`noUncheckedIndexedAccess` friction in the `.ts` files.** `depthLadder[i]` is
  `number | undefined` under this project's `tsconfig`. Guard it rather than casting with
  `!` — and never relax a `compilerOption` to make the code compile. If a strictness flag
  genuinely blocks the specified design, report **Blocked / unclear**. (This does not apply
  to `dom-prune.js`, which is not type-checked.)

- **Test 8's `tokenCeiling: 20` override produces an identical html at every rung.** If the
  app's pruned tree is shallower than the smallest rung (2), the ladder cannot shrink it and
  the "strictly shorter" assertion fails. The app's tree is `html > body > main > section >
  article > button` (depth ≥ 5), so depth 2 does shrink it. If the assertion nonetheless
  fails, do not weaken the assertion to `<=` — investigate whether the depth limit is being
  applied at all.

- **The second Playwright config fights the first over port 3100.** Both set
  `reuseExistingServer: true`, so running them sequentially is safe. Running them
  concurrently is not supported and is not required. If `npm run test:tools` reports
  `EADDRINUSE`, a stray server is running — stop it; do not change the port.

- **Test 9 launches a second browser inside a running Playwright test.** This is legal but
  slower; hence `timeout: 30_000` in the tools config. If it still times out, raise only
  that config's timeout, never `playwright.config.ts`'s.

- **Whitespace collapsing changes text assertions the model will later rely on.** Collapsing
  and trimming means `<span>a</span> <span>b</span>` renders as two lines with no space
  between the words when flattened. This is accepted for v1 and documented; it does not
  affect any selector in the app under test. Do not add inline-element special-casing to
  "fix" it.

- **Scope creep toward Task 2.2.** A snapshot tool that also reports match counts is
  Task 2.2's job. If the Builder finds itself writing `querySelectorAll(candidate)` in
  `get-dom-snapshot.ts`, it has left this task.

- **Temptation to give the agent a better hook.** Adding a `data-testid` to
  `app-under-test/index.html`, or allowlisting `data-*` so the agent has a drift-proof
  selector, would silently invalidate the entire self-healing demonstration. Both are
  forbidden by `app-under-test/README.md` and by this plan.

- **The token ceiling is a heuristic, not a guarantee against a real tokenizer.** 4000
  estimated tokens could be more or fewer real tokens. The headroom (measured app snapshot
  is expected around 450) makes this immaterial for v1. Do not "fix" it by adding a
  tokenizer dependency; if Phase 3 shows the estimate is materially wrong, that is a
  separate task.
